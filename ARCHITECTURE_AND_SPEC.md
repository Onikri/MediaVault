# MediaVault: пакетный перевод манги

Реализация 27 октября 2026. Канонический сайт — `Onikri/MediaVault`.

## Два режима

**Полностью локально.** Детектор, OCR, Hy-MT2 / Index / WebLLM, очистка и набор работают в браузере. Переключение сбрасывает прежний режим удалённого LLM API. Страницы не отправляются в сервис перевода. Загрузка весов требует явного включения. ВМ для этого режима не нужна.

**ВМ.** Данные идут Drive → Oracle → Gemini API (бесплатные Gemma 4). На устройство возвращаются исходные координаты и проверенный JSON перевода. Очистка и набор работают на устройстве. Старый Hy-MT2 / Index + серверная LaMa оставлены в подразделе сравнения: они не участвуют в быстром пути.

## Сервер

`server/manga_batch` — отдельный FastAPI-сервис, один процесс, два асинхронных сетевых работника; CPU-детекция сериализована и вынесена через `asyncio.to_thread`. ONNX: постоянная сессия, CPUExecutionProvider, ORT_ENABLE_ALL, ORT_SEQUENTIAL, intra=2 / inter=1. Подтверждённый RT-DETR v4 INT8 весит **11 120 765 байт**, SHA-256 закреплён в коде.

Существующий importer **не пересобирается и не перезапускается**. Новый доверенный сервис читает его настройки только из read-only mount: HMAC сессии, OAuth refresh token и клиент Google. Он не создаёт TaskStore, который при запуске выполняет восстановление очереди. Полномочия этого сервиса сопоставимы с importer; он не должен быть доступен без авторизации.

Открытие главы передаёт существующий производный ключ библиотеки по HTTPS, как серверный импорт. Фраза не передаётся. Ключ живёт только в памяти сеанса 30 минут, не сохраняется в кэш. Проверяются владелец Drive, расшифрованный каталог, принадлежность главы и список ZIP-страниц. Нельзя указать произвольный URL или Drive-файл вне каталога. CBZ читается диапазонами через AES-GCM части по 4 МиБ; RAM LRU ограничен четырьмя частями на сеанс. Не более четырёх сеансов.

Детектор отбрасывает confidence <0.35 и размеры <12 px. Вложенные text_bubble и bubble становятся одной репликой с `text_bbox`, `bubble_bbox` и `layout_bbox`. Несколько реплик в одном облачке получают разные области набора. ID стабилен относительно главы: P1_B1… Координаты модели перевода не принимаются.

SoM копии: RAM/Pillow → красные рамки и уникальные UID → WebP q80, до1280px. До четырёх изображений и65 областей за вызов. Плотная страница разбивается на несколько запросов, каждый получает только свои метки. До полного валидного ответа страница не кэшируется. Ответ неполон → пакет делится на меньшие фрагменты вплоть до одной области; номера не угадываются. Многополосный запрос, не завершившийся за45с, тоже делится, сохраняя учёт квот. Одиночная страница сохраняет собственный тайм-аут SDK.

Официальный SDK `google-genai==2.33.0`; модели `gemma-4-31b-it` и `gemma-4-26b-a4b-it`. Thinking **MINIMAL**, а не неподдерживаемое для этой семьи LOW. Системный промпт пользователя хранится в `prompt.py`. Строгая схема плюс собственная проверка полноты UID, повторов, типов и связей. Если модель отвергает structured output, используется JSON-инструкция с такой же собственной проверкой. Исходная ошибка не превращается в «успешную» страницу.

CountTokens перед запросом, резервирование токенов + запас на схему, сверка с usageMetadata. Скользящее окно60с:13000 TPM /14 RPM — **настраиваемый бюджет**, не заявление о фактической квоте аккаунта. По умолчанию общий пул проекта. Раздельные пулы включаются только после подтверждения quota dimensions Google. 429 уважает RetryInfo; неизвестный лимит считается общим. Отклонённые429/400 и ошибки500/502/503 освобождают неподтверждённый резерв входных токенов, сохраняя запись RPM; неоднозначный504 сохраняет резерв. Ошибка5xx многополосного запроса вызывает разделение вместо бесконечного повтора полного пакета. SSE остаётся открытым. Платный Gemini fallback не включён. Никакой ротации ключей для обхода квот.

## Кэш и доставка

- POST `/api/v1/chapters`: открыть проверенную главу Drive.
- GET `/api/v1/chapters/{id}/stream?currentPage=N`: авторизованный fetch SSE, JWT в заголовке, не URL.
- POST `/api/v1/chapters/{id}/touch`: сдвиг окна N…N+11.
- DELETE `/api/v1/chapters/{id}`: закрыть сеанс и освободить ключ после завершения разделяемой работы.
- GET `/api/v1/manga-translation/status`: состояние и версия политики.
- POST `/api/v1/manga-translation/key`: установить ключ AI Studio из настроек владельца. Ключ не попадает в localStorage/логи/ответ.

Приоритеты: первые4 страницы, следующие4, последние4. Singleflight на **страницу**, чтобы перекрывающиеся окна не дублировали платёж/квоту. Redis — ограниченный горячий кэш; SQLite WAL — постоянный зашифрованный JSON. В Redis передаются зашифрованные значения и уведомления готовности. В одном поддерживаемом процессе fanout подписчиков использует общие Future; масштабирование на несколько процессов требует распределённых lease/PubSub consumers, **оно сейчас не включено**. Uvicorn workers=1 обязателен.

Ключ кэша включает владельца, библиотеку, manifest (ID/размер/Drive-части/IV/порядок страниц), направление, версии детектора, промпта и схемы. Оригиналы и SoM в SQLite не сохраняются. Redis недоступен → SQLite. Кэш без TTL в SQLite сохраняется до явного обслуживания диска; размер диска нужно контролировать. JSON не обязательно2–3КБ: зависит от числа и длины реплик.

## Клиент

Исходный скан отображается сразу. `VmChapter` читает поток и сохраняет **зашифрованный JSON** в IndexedDB с изоляцией профиля/библиотеки. Повторное чтение из локального кэша не открывает серверное задание. Рендерятся видимые страницы, а не все12 сканов одновременно.

Быстрый режим: Web Worker, OffscreenCanvas, оценка цвета периметра, маска контрастных букв с расширением, адаптивная заливка плоских бабблов; Telea на сложном фоне. Кириллические OFL-шрифты Comic Relief, Pangolin, Neucha, serif/mono для соответствующих стилей. Бинарный поиск10…42px, реальные метрики шрифта, овальная балансировка строк,10% отступы. Невместившаяся реплика сохраняет оригинал и доступна целиком в текстовом просмотре.

LaMa Manga206МБ — отдельный добровольный режим качества на устройстве через существующий движок ONNX/WebGPU/WASM. Он медленнее быстрого worker; не нужно представлять его как несуществующую «LaMa-Manga-Micro». Быстрый режим не требует скачивания нейросетей на телефон.

Worker передаёт готовый ImageBitmap напрямую в Canvas без дополнительного кодирования в WebP. Новый слой лежит поверх постоянно смонтированного оригинала. Alt или длительное нажатие временно скрывают русский слой. Переключатель оригинала не меняет исходные файлы.

## Проверка и ограничения

`tests/test_manga_batch.py`: реальные ZIP/AES/SQLite/геометрия, модель Google — явно обозначенные фикстуры. `tests/manga-vm-browser.cjs`: настоящий Worker/OffscreenCanvas/кириллические шрифты/очистка и шифрованный IndexedDB, серверный ответ — фикстура. `scripts/benchmark-manga-batch.py` измеряет настоящий ONNX и SoM отдельно от API.

Первый локальный замер x86_64: тёплая детекция ≈780мс/страница, SoM≈16мс, холодная сессия≈16.5с. Настоящий Canvas Worker на тестовом скане600×850: очистка8.2–26.9мс, набор0.2–0.9мс, весь рендер16.1–77.9мс (первый вызов включает загрузку шрифтов). При параллельной сборке контейнера рендер доходил до123мс; эти дополнительные замеры также сохранены. Это **не замер физического телефона или Oracle A1**. Цифры45мс /3.8с на4 страницы /2–40мс клиентского рендера из исходного ТЗ не считаются достигнутыми без замеров на соответствующем оборудовании. Работа Google API и качество перевода проверяются отдельно с ключом владельца; фикстуры этого не доказывают.

На реальной Oracle A1 (2 OCPU /12ГиБ, ARM64) измерены: прогрев ONNX406мс, медиана детекции341мс, SoM155мс на публичном скане3430×2417. Зашифрованный Redis JSON: медиана0.128мс, SQLite-hit0.439мс, чужой scope отвергается. Реальный тест одной страницы через Gemma 4 31B вернул4/4 проверенных реплики: первый проход18.764с (Google17.478с), повторная выдача0.353мс. Это тест публичного RAM-скана, не расшифрованной главы Drive и не независимая оценка качества перевода. Результат сохранён в `docs/benchmarks/manga-batch-oracle-a1-2026-10-27.json`.

Предельная страница10МиБ /24Мп. Очень длинный вебтун теряет мелкий текст при уменьшении до1280px: этот режим требует сегментации скана и отдельных визуальных фрагментов; нельзя обещать такую же точность, как у обычной страницы. Собственная нейросеть инпейнта на ВМ в быстром пути отсутствует.

## Развёртывание

`deploy/oracle/compose.manga-batch.yaml` — overlay для ARM64: сервис2ГиБ + Redis192МиБ. Никаких новых облачных ресурсов или публичных портов. Caddy добавляет только `/api/v1/*` с отключённой буферизацией SSE. Остальные маршруты, importer, библиотека и парсеры остаются прежними.

Перед установкой: проверить свободное место и память, существующие bind mounts и сеть, сохранить конфигурацию Caddy, проверить кандидата внутри Docker-сети, затем reload Caddy. При ошибке вернуть конфигурацию. Установить ключ через закрытую форму на сайте. Сначала замерить реальные4 страницы и повторный кэш-hit, затем менять скорость/модели на основании результатов.

Официальные источники: https://ai.google.dev/gemma/docs/core/gemma_on_gemini_api ; https://ai.google.dev/gemini-api/docs/pricing ; https://ai.google.dev/gemini-api/docs/rate-limits . Google подтверждает бесплатный API Gemma4, но фактические лимиты определяются проектом и могут меняться.
