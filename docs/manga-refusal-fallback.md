# Запасной перевод баблов, которые отклонил Google

Google отказывается переводить часть страниц взрослой манги, манги с насилием и хентая. Отказ приходит как HTTP 200 без кандидатов с `promptFeedback.blockReason` (обычно `PROHIBITED_CONTENT`) или как стоп-причина кандидата `SAFETY`, `PROHIBITED_CONTENT`, `BLOCKLIST` и т. п. Раньше ридер принимал такой ответ за «незавершённый JSON», баблы оставались без перевода, а глава — со «страницами с пропусками».

## Как это работает

1. **Распознавание.** `validateDirectResponse` выбрасывает `GoogleRefusal` (`error.refusal`). В диагностике запроса стадия `refused`, а не ошибка JSON.
2. **Сначала снова Google** (`src/manga-refusal.js`). Отклонённый пакет делится по шагам: пакет страниц → каждая страница отдельно → вырезки баблов этой страницы без рисунка → половины → один бабл. На деление одного пакета уходит не больше 6 дополнительных запросов (`SPLIT_BUDGET`, у каждого запроса пауза ключа 4 с). Остаток сразу помечается `refused`. Повторная проверка пустых ответов не отправляет отклонённые баблы снова, а её собственные отказы делятся так же.
3. **Запасная модель на ВМ** (`src/manga-fallback.js`, `DirectChapter.settle`). Перед `finish()` страница с нерешёнными баблами асинхронно отправляет на ВМ вырезки только этих баблов в исходном разрешении: `POST /reader/lmt/fallback`. Ключ Google к этому моменту уже освобождён, поэтому остальные страницы главы переводятся параллельно. На ВМ работает тот же OCR, что в LMT: manga-ocr для японского, PP-OCRv5 Korean, Paddle English, со скрипт-гейтом. Затем Hy-MT2 1.8B Q8 через llama.cpp переводит каждую реплику отдельно. Английский текст из капса сначала приводится к обычному регистру.
4. **Тот же формат.** Ответ вливается в `page.regions` (`ru_translation` и `region.fallback={model,ocr,status,reason,source}`), геометрия не меняется. Очистка, кириллическая вёрстка, кэш страницы и рендер остаются прежними. Онлайн-чтение и скачивание на ВМ (`manga-export-runtime.js`) получают страницы без пропусков. Если OCR не находит букв, область считается `non_text` и сохраняет оригинал.
5. **Если ВМ недоступна,** страница остаётся с пропусками и `detectionReport.fallbackError`. В конце главы `recoverChapter()` повторяет и Google, и запасную модель.

Языки: только японский, корейский и английский → русский. Для китайского запасной перевод не запускается.

## Диагностика ридера

- **«Рамки»:** баблы помечены «· запасная» (синие) или «· отказ Google» (розовые). Над рамками перечислены отклонённые и переведённые запасной моделью ID, с моделью и OCR.
- **«Очередь»:** строка «Запасная модель · реплики» (`snapshot().preparation.fallback`). У страницы, которую сейчас переводит ВМ, состояние «запасная модель на ВМ».

## Проверки

**С моками API (не доказывают качество моделей):**
- `tests/manga-refusal.test.mjs` (в `npm test`): распознавание отказа; порядок деления; на ВМ уходит только оставшийся бабл; ключ свободен во время запасного перевода; бюджет деления; non_text и ошибки по баблам; повтор после ошибки ВМ; только JA/KO/EN; путь VM-экспорта.
- `tests/test_lmt_fallback.py`: статусы по каждому баблу; шум не попадает в переводчик; проверка вырезок; маршрут только для владельца; отказ для неподдерживаемых языков; ошибки без утечки путей; общий замок OCR со страничным конвейером LMT; нормализация английского регистра.

**Реальный инференс на Oracle VM (2026-11-12),** `scripts/benchmarks/refusal-fallback-vm.py`, данные в [`benchmarks/refusal-fallback-oracle-2026-11-12.json`](benchmarks/refusal-fallback-oracle-2026-11-12.json):
- Hy-MT2 на 14 взрослых и жестоких репликах JA/KO/EN: отказов 0, 0,7–2,9 с на реплику (первая после простоя 13,9 с).
- 49 реальных вырезок (13 JA, 2 KO, 34 EN), по 3 бабла на запрос, как на одной странице. 2 vCPU делятся с рабочими контейнерами.

| | OCR, медиана на бабл | Hy-MT2, медиана | запрос из 3 баблов | CER OCR |
|---|---|---|---|---|
| японский | 4,1 с | 2,5 с | 16–26 с | 0,138 |
| корейский (2 бабла) | 1,8 с | 3,2 с | 7–10 с | 0,193 |
| английский | 0,25 с | 2,0 с | 4–18 с | 0,193 |

Первый запрос после запуска Chromium и загрузки OCR — 26–54 с. Переведено 46 из 49 баблов: 2 вырезки OCR признал нетекстом, на 1 модель вернула текст без перевода.

Качество ниже Gemini, но смысл обычно сохраняется. Типичные ошибки: путаница с местоимениями и родом, буквальные звукоподражания. Хуже всего японские реплики с подразумеваемым смыслом (например, «中に出していい？» переведено неверно). Запасная модель закрывает пропуски, но не заменяет Google.

## Ограничения

- Режим «Google сам находит текст» (`vision`) не делится: локальных областей нет, отказ остаётся ошибкой страницы.
- `/reader/lmt/fallback` доступен только сессии владельца. По share-ссылкам пропуски остаются.
- Страница, где Google отказал во всех японских баблах (10+), на ВМ занимает около минуты: manga-ocr — самая медленная часть.
