# Подготовка главы, пакетный перевод и набор

## Конвейер

При включении перевода подготавливается вся текущая глава. До четырёх загрузок
исходников, две задачи подготовки детектора, очередь очистки и запросы Google
работают независимо. В режиме экономии трафика число фоновых задач снижается.
Детектор модели выполняется в своём worker; обработка одной страницы не ждёт
перевода предыдущей. Очистка начинается сразу после получения координат.

Единый диспетчер отправляет пакеты в порядке страниц. По умолчанию запрос содержит
две страницы; можно выбрать три. Остаток из трёх страниц отправляется вместе.
Одновременно обрабатываются до трёх пакетов и девяти исходных страниц, с учётом
реального количества настроенных ключей. Ключи чередуются; общий для экземпляров
читалки ограничитель выдерживает интервал не менее четырёх секунд и максимум
15 запросов за скользящую минуту на ключ. Квоты Google-проекта применяются отдельно.

Плотные страницы сохраняются вместе: при превышении бюджета 100 текстовых ID
делится список запрашиваемых ID, а не пара изображений. Контекст соседних страниц
сохраняется. Сетевой тайм-аут остаётся явной настройкой; прежний искусственный
лимит подготовки блока в 1,8 секунды в новом конвейере не используется.

Подготовленный фон хранится отдельно от JSON перевода. Маски сохраняются в виде
серий пикселей, поэтому после ответа API на страницу переносятся только области
подтверждённых переводов. Отвергнутый моделью нетекстовый блок остаётся исходным.
Набор выполняется после получения перевода и фона; результат показывается атомарно.
Повторная очистка использует готовый JSON и не отправляет перевод заново.

## Режим «Блоки»

Это способ упаковки входа API. Обычный режим и «Блоки» используют один выбранный
детектор, исходные координаты, область набора и тот же рендерер. Переключение
детектора меняет вариант кэша. Отдельный экспериментальный блочный детектор
не подменяет выбор пользователя.

Вырезки размещаются в свободных прямоугольниках листа без изменения масштаба,
с рамкой и исходным ID. Размер запроса ограничивают читаемость, пиксели и количество
областей, а не фиксированное число исходных страниц. ID задают порядок чтения.
Связанные фрагменты на стыках вебтуна обрабатываются совместно; обычным блокам
сохраняется исходная область вёрстки, независимо от размещения на листе.

## Очистка и шрифты

- Moebius получает маску с обеими полярностями штрихов, расширением для обводки
  и дополнительным запасом сверху. Длинные рамки за пределами текста защищаются.
  Общая маска обрабатывается за один проход; её ограничивающий прямоугольник
  получает контекст и используется для входа 512 × 512 без потери масштаба на
  неиспользуемых частях страницы. Это не устраняет ограничения самого генератора.
- Быстрая очистка учитывает белые и тёмные штрихи. Для узких текстовых полос на
  рисунке используется полная ограниченная маска и Telea, чтобы не оставлять
  обводку между отдельными иероглифами. Соседние рамки защищаются.
- Если безопасная очистка не удалась, русский текст показывается чёрным с белой
  округлой подложкой примерно на три пикселя вокруг букв. Такой результат отмечен
  `white-lettering` и не выдаётся за успешно восстановленный фон.
- Цвет успешного набора выбирается по восстановленному фону, а не по исходной
  границе блока. Это исправляет белый перевод на уже светлом фоне.
- Русские переносы используют шаблоны `hyphen/ru`; запрещены односимвольные части
  слова и отрыв ь/ъ/й от предыдущей части. Целые слова сначала переносятся целиком.
- Запрос отличает роль текста от засечек японского Mincho. Обычные реплики
  используют кириллический Comic Relief; добавлены автоматические стили Pangolin
  и Neucha. Для документов, рукописи, игровых сообщений и SFX остаются отдельные
  стили. Шрифты выбираются из локального лицензированного набора.

MI-GAN добавлен отдельной моделью CPU/WASM: официальный ONNX pipeline Places2,
28 079 181 байт, закреплённая ревизия и SHA-256 в `src/migan-model.js` и манифесте.
Маска uint8 использует 0 для удаляемых пикселей и 255 для известных. Выход модели
переносится только внутри маски. Модель кэшируется в выбранной папке либо в кэше
браузера; загрузка нейросетевого инпейнта требует соответствующего разрешения.
Подготовка, очистка и набор используют разные пулы worker, чтобы тяжёлая модель
не загружалась повторно из-за передачи её worker лёгкой подготовке.

## Хранение и диагностика

Исходники, координаты и фоны текущей главы сохраняются на устройстве чтения
зашифрованными, отдельно для профиля и библиотеки: до 1 ГБ, семь дней. Буфер
исходников в памяти ограничен девятью страницами. Кэш перевода — до 1000 записей
и 256 МБ. При недоступности хранилища используется память. Это браузер телефона
или компьютера, на котором открыта читалка; доступ к Windows-диску D не требуется.
Существующий серверный кэш Oracle остаётся отдельным уровнем.

Отладка показывает исходные рамки, фактическую оранжевую маску, фон до набора,
запрос, очередь по порядку страниц и состояния ключей без их значений.

## Проверки

- Node: 193 теста. Производственная сборка основного приложения и LMT.
- Браузерные контракты: обычные пары, «Блоки», стыки вебтуна, очистка, MI-GAN,
  восемь реальных шрифтов, читалка на мобильной и широкой вёрстке.
- Реальный Google через Oracle: 6 синтетических страниц отправлены как 1–2,
  3–4, 5–6, по два изображения, три ответа HTTP 200. На ВМ фактически настроен
  один серверный ключ; ротация трёх проверяется отдельным контрактным тестом.
- Реальные «Блоки» через Google: 6 страниц → 1 PNG-лист, 6 ID, HTTP 200 / STOP.
- Реальный MI-GAN в браузерном worker: WASM, проверенные веса, отдельная подготовка
  фона и повторный набор с нулём дополнительных вызовов модели. Это настольный
  тест; скорость на физическом телефоне не измерялась.
- Moebius: реальный ONNX CPU reference с той же маской и геометрией; изменения
  вне маски — ноль. Браузерный WebGPU-прогон не завершился из-за ошибки выделения
  памяти GPU. CPU-проверка не считается измерением WebGPU или оценкой качества.
- Полный Python-набор выполняется в Linux CI перед публикацией. Локально на
  Windows остаются четыре прежние ошибки POSIX/SQLite в 362 тестах, семь пропусков.

Численные результаты реального инференса отделены от контрактов в
`docs/benchmarks/reader-pipeline-live-2026-10-30.json`. Пользовательские изображения,
веса моделей, профили браузера и токены в исходники не включены.

## Исправление очереди нейронного детектора

Две асинхронные задачи подготовки главы используют общий экземпляр LMT.
Модуль принимает их в FIFO-очередь: ONNX-инференс одного движка выполняется
по одному, без ошибки «Предыдущая страница ещё обрабатывается» и без потери
второй страницы пакета. Ошибка одной задачи не отклоняет следующие.
Загрузка исходников, очистка и API продолжают работать независимо.
Загрузчик обновляет адрес iframe, чтобы не использовать старый HTML из кэша.

Регрессия: два Node-теста очереди и браузерная проверка нескольких одновременных
сообщений в собранном LMT-модуле, включая восстановление после ошибки. Эта
проверка IPC не считается реальным ML-инференсом.

## Управление запуском и навигацией

Открытие главы не включает перевод, даже если он был включён при предыдущем
закрытии. Вся глава кэшируется независимо; детекция, очистка и API запускаются
только кнопкой перевода. Личные ключи — режим по умолчанию нового профиля;
явный выбор серверного режима сохраняется. При личном режиме слоты Oracle
не запрашиваются и не подставляются вместо отсутствующего ключа.

При дальнем переходе текущие API-пакеты завершаются. Выбранная страница и три
следующие получают приоритет на одном ключе; другие ключи продолжают обычную
очередь. Затем обрабатываются пропущенные страницы. Детектор и очистка также
переходят к этому окну после завершения своих текущих операций. Отладка считает
скачанные, размеченные, очищенные, ошибочные и переведённые страницы отдельно;
история сохраняется для всей главы, а не последних 12 страниц.

«Соседних изображений в памяти» управляет отрисовкой, а не размером главы или
буфером API. Смена настроек создаёт новые версии фонов и набора; прежний слой
виден до готовности замены. Старые версии не удаляются массово.

Быстрая очистка больше не создаёт заполненную вертикальную полосу. Белые
замкнутые пузыри используют цвет бумаги; контурные буквы включают замкнутые
тёмные внутренности. MI-GAN использует отдельный радиус 2–3 px с защитой рамок,
Moebius сохраняет свой больший радиус. Набор расширяется в обнаруженный замкнутый
светлый пузырь; открытая белая страница отвергается. Высокие свободные надписи
могут набираться с поворотом, вместо уменьшения русского текста до узкой строки.

## Проверка масок на пятой главе ATM Ojisan

После публикации основного обновления выполнено сравнение страниц 9 и 10:
реальные RT-DETR и MI-GAN ONNX/WASM, контролируемые русские реплики без вызовов
Google, отдельный реальный CPU reference Moebius. Числа и ограничения сохранены
в `docs/benchmarks/reader-masks-atm5-2026-10-30.json`; изображения остаются приватными.

Для этих страниц (1920 px) выбран радиус MI-GAN 2 px. Дополнительный пиксель
не дал устойчивого улучшения, а на цветной надписи увеличивал артефакты.
Серые пятна модели на полутоне не следует считать просто оставшимся оригинальным
текстом: входная маска покрывала больше 99,9% его тёмных пикселей. Полярность
и формат соответствуют [контракту авторов](https://github.com/Picsart-AI-Research/MI-GAN#for-developers).
Алгоритмическая очистка устраняет прежние чёрные центры карточек, однако сложная
текстура всё ещё может сглаживаться; нейросетевая реставрация тоже не идеальна.

По результатам сравнения ограничение поиска светлого пузыря теперь уменьшает
окно поиска вместо отказа; тестовый набор в большом пузыре увеличился 31 → 45 px.
Отладка использует входную маску модели, отдельно от области копирования пикселей.
В MI-GAN и Moebius переносится только маска модели; для края LaMa сохранена
отдельная запись фактической входной маски. Фоны/набор получают версию v9.


## Пустой ответ на найденную реплику

На странице 17 пятой главы ATM Ojisan воспроизведён случай из скриншота:
реальный RT-DETR нашёл 14 областей, а контролируемый пустой ответ для P17_B2
оставлял 13 переводов. Раньше пустой ответ назывался «без читаемого текста»,
а маска отладки показывала только области, использованные при итоговом наборе.
Это не доказывало отсутствие букв или маски фоновой очистки.

Теперь непереведённые области пакета один раз проверяются вместе на листах
увеличенных вырезок (до 2×). Проверка использует тот же занятый ключ и общий
ограничитель частоты; максимум одно дополнительное обращение на исходный
пакет, без отдельных запросов на каждый блок. Модель отдельно помечает
подтверждённый не-текст и неразборчивый текст. Ошибка проверки, включая 429,
не уничтожает уже полученный перевод; незавершённые страницы отмечаются
отдельно и не входят в число полностью переведённых. Старый частичный JSON
проверяется без повторной отправки готовых реплик, результат проверки
сохраняется; ручной повтор страницы позволяет запросить перевод заново.

Маска и фон в отладке относятся ко всей фоновой очистке, включая области
без перевода. Отдельно указано, какие области очищены, но не переведены,
и почему очистка отказала. В итоговой странице непереведённая реплика
сохраняет исходный текст до получения перевода. Для уже переведённой реплики
при неудаче очистки по-прежнему используется чёрный русский текст с белой
подложкой. Кэш итогового набора v10; существующие фоны v9 переиспользуются.

Проверки: реальные браузерные вырезки/маски/очистка/набор с контролируемыми
ответами, тесты очереди с успешной проверкой, квотой и старым кэшем. Это
контрактные тесты перевода, а не замер качества Gemini. На реальной странице
17 для P17_B2 получена маска 33 716 пикселей внутри исходной рамки;
алгоритмическая очистка выполнялась, исходник при пустом ответе сохранён.
Изображения и диагностические артефакты остаются в приватной .codex-local.
