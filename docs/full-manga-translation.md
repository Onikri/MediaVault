# Полный перевод в читалке

Читалка использует готовую страницу Libre Manga Translator: детекция → OCR → перевод → inpainting → русский набор. Старый `/reader/translate`, возвращавший текст с маркерами, больше не используется читалкой.

## Профиль качества

- ВМ Oracle: Hy-MT2 1.8B Q8 (официальный prompt), RT-DETR, LaMa Manga, Comic Relief.
- OCR: Paddle для EN/CN, Manga-OCR для японского, PP-OCRv5 для корейского.
- Устройство: те же детекторы / OCR / очистка, WebLLM Qwen 3.5 4B. Hy-MT2 GGUF не объявляется браузерной моделью. Для локального LLM нужен WebGPU.
- Свой API остаётся дополнительным режимом: OCR/очистка на устройстве, текстовая или vision-модель на своём сервере.

См. реальные тесты кандидатов в [отчёте](manga-model-comparison-2026-10-26.md). Ни один машинный переводчик не гарантирует литературную точность.

## Автовёрстка

Шрифт загружается перед измерениями. Для каждой реплики подбираются переносы и кегль, проверяется высота и ширина строк, затем текст центрируется внутри исходной области. Переполнение вызывает ошибку, не молчаливую потерю текста. При неудаче OCR/очистки возвращается предупреждение; неполные страницы не сохраняются в постоянный кэш. Отдельный список реплик доступен под готовой страницей; числовые метки поверх готового изображения скрыты.

## Очередь и кэш

Видимые страницы имеют приоритет над ожидающей предобработкой. По умолчанию готовятся две следующие страницы, при экономии трафика предобработка отключается. При смене главы/профиля или блокировке текущая очередь отменяется. На устройстве сохраняется до 160 страниц / 192 МБ: AES-GCM, отдельный ключ CryptoKey для профиля и библиотеки в IndexedDB. Ключ позволяет читать сохранённые переводы на этом устройстве после перезагрузки; это не экспорт секрета библиотеки. Оригинальный CBZ не меняется.

На ВМ готовые изображения сохраняются отдельно от Drive в AES-GCM кэше до 512 МБ / 7 суток. Ключи включают пользователя, SHA страницы и параметры моделей/шрифта/версию конвейера. ВМ принимает только проверенную сессию владельца; фоновые процессы не получают Google OAuth, ключ открытой библиотеки или доступ к файловому каталогу импортера.

## Установка на существующую ВМ

`deploy/oracle/install-lmt.py FULL_REVIEWED_SHA` собирает два приватных sidecar-контейнера и добавляет `/reader/lmt/*` в существующий Caddy. Используется ранее проверенный llama.cpp b11887 и уже скачанный Hy-MT2 с проверкой SHA. ONNX кэш прошлых испытаний переиспользуется. Новых облачных ресурсов и публичных портов нет. Контейнер импортера не перезапускается, настройки и данные не монтируются в LMT. Лимиты памяти: LMT 6 ГБ, LLM 3 ГБ.

Команды установки требуют доступа к ВМ; наличие кода в GitHub само по себе не означает, что sidecar уже установлен. После установки проверяются public status, запрет анонимного запуска и реальная обработка с очисткой и набором, повторное чтение из кэша.

## Проверки

Node-тесты проверяют миграцию старого режима, идентичность кэша, очередь, отмену и контракт готовой страницы. Python-тесты проверяют шифрование, изоляцию владельца, кэш, отмену, повторный запуск и проверку сессии. Browser-тест использует явно синтетическую готовую страницу: проверяет читалку, предобработку, повторное открытие, переключение места обработки и отсутствие маркеров. Это не тест качества моделей.
