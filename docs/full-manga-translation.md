# Полный перевод в читалке

Читалка использует готовую страницу Libre Manga Translator: детекция → OCR → перевод → inpainting → русский набор. Старый `/reader/translate`, возвращавший текст с маркерами, больше не используется читалкой.

## Профиль качества

- ВМ Oracle: Hy-MT2 1.8B Q8 (официальный prompt), RT-DETR, LaMa Manga, Comic Relief.
- OCR: Paddle для EN/CN, Manga-OCR для японского, PP-OCRv5 для корейского.
- Устройство: настоящий Hy-MT2 GGUF через wllama, WebGPU либо CPU/WASM. Q8 (1,91 ГБ), Q6 (1,47 ГБ), Q4 (1,13 ГБ); веса проверяются SHA-256 и сохраняются в OPFS. Index Translate 2B — отдельный профиль Q8/Q6/Q4 (2,08 / 1,61 / 1,31 ГБ). Qwen оставлен экспериментальным вариантом. На GitHub Pages без cross-origin isolation CPU/WASM однопоточный. Загрузка начинается только после согласия; при недостаточной квоте загрузка не начинается.
- Свой API остаётся дополнительным режимом: OCR/очистка на устройстве, текстовая или vision-модель на своём сервере.

См. реальные тесты кандидатов в [отчёте](manga-model-comparison-2026-10-26.md). Ни один машинный переводчик не гарантирует литературную точность.

## Автовёрстка

Шрифт загружается перед измерениями. Для каждой реплики подбираются переносы и кегль, проверяется высота и ширина строк, затем текст центрируется внутри исходной области. Переполнение вызывает ошибку, не молчаливую потерю текста. При неудаче OCR/очистки возвращается предупреждение; неполные страницы не сохраняются в постоянный кэш. Отдельный список реплик доступен под готовой страницей; числовые метки поверх готового изображения скрыты.

### Набор по форме облачка (2026-11)

Оба пути набора — рендерер читалки (`src/manga-renderer.js`, режимы «Быстрый» и «ВМ → Google») и классический конвейер (`lmt/entry.js`) — используют модуль `lmt/typeset/`:

- Текст вписывается в реальную внутренность облачка (заливка бумаги по строкам), а не в прямоугольник, и центрируется по центру фигуры. Облачко, обрезанное краем страницы, не «дорисовывается».
- Один средний кегль реплик на страницу (не больше 3,4 % ширины страницы), слегка подстраивается под размер облачка; меньше — только когда текст не помещается. Крик набирается крупнее.
- Перенос слова по слогам (не меньше двух букв с каждой стороны) делается только когда слово не помещается, и раньше уменьшения кегля. Знаки препинания остаются на концах строк, предлоги и частицы не отрываются от слова.
- Основная гарнитура — для реплик, мыслей (наклонное начертание) и криков. Отдельные гарнитуры только для авторского текста, звуков, мелких фраз в стороне и надписей.
- Связанные области вебтуна и вертикальные надписи набираются прежним построчным алгоритмом.
- Настройка «Набирать реплики заглавными» включена по умолчанию; выбор входит в ключ кэша.

Реплика, которая не помещается, не набирается: исходные буквы сохраняются, страница получает предупреждение.

### Приватные шрифты владельца

Шрифты, на которые у владельца есть собственная лицензия, не входят ни в репозиторий, ни в публичную сборку сайта. Файлы `.otf/.ttf/.woff2` кладутся на ВМ в `<LMT data>/reader-fonts/` (по умолчанию `/opt/mediavault-lmt/data/reader-fonts/`). Сервис LMT отдаёт их только проверенной сессии владельца (`GET /reader/lmt/fonts`, `GET /reader/lmt/fonts/{n}`); читалка хранит байты в Cache Storage этого браузера и передаёт их обработчику страниц. Собственный браузер ВМ получает те же файлы локально. Роль определяется по имени файла (`reader-fonts/catalog.js`): звуки, мелкие фразы, надписи. Без этих файлов используются открытые шрифты. Локальная сборка подхватывает такие же файлы из `reader-fonts/local/` (в `.gitignore`).

### Быстрая очистка

Telea (`lmt/upstream/lib/inpaint/telea.ts`) идёт без кучи: расстояние до границы маски считается двухпроходным преобразованием 3-4, порядок обхода — сортировкой подсчётом. Перед ней `tone.ts` восстанавливает периодический фон (скринтон, штриховка), копируя узор из соседнего периода; на гладком фоне, градиенте и одиночных линиях ступень не срабатывает. Сравнение: `scripts/benchmarks/telea-bench.mjs` (синтетические фоны, без нейросетей).

Проверки набора: `tests/manga-typeset.test.mjs` и `tests/manga-inpaint.test.mjs` — чистая логика; `tests/manga-typeset-browser.cjs` и `tests/manga-bubble-layout-browser.cjs` — настоящие шрифты и Canvas на нарисованной странице, без детектора, OCR и перевода.

## Очередь и кэш

Видимые страницы имеют приоритет над ожидающей предобработкой. По умолчанию готовятся две следующие страницы, при экономии трафика предобработка отключается. При смене главы/профиля или блокировке текущая очередь отменяется. На устройстве сохраняется до 160 страниц / 192 МБ: AES-GCM, отдельный ключ CryptoKey для профиля и библиотеки в IndexedDB. Ключ позволяет читать сохранённые переводы на этом устройстве после перезагрузки; это не экспорт секрета библиотеки. Оригинальный CBZ не меняется.

На ВМ готовые изображения сохраняются отдельно от Drive в AES-GCM кэше до 512 МБ / 7 суток. Ключи включают пользователя, SHA страницы и параметры моделей/шрифта/версию конвейера. ВМ принимает только проверенную сессию владельца; фоновые процессы не получают Google OAuth, ключ открытой библиотеки или доступ к файловому каталогу импортера.

## Установка на существующую ВМ

`deploy/oracle/install-lmt.py FULL_REVIEWED_SHA` собирает два приватных sidecar-контейнера и добавляет `/reader/lmt/*` в существующий Caddy. Используется ранее проверенный llama.cpp b11887 и уже скачанный Hy-MT2 с проверкой SHA. ONNX кэш прошлых испытаний переиспользуется. Новых облачных ресурсов и публичных портов нет. Контейнер импортера не перезапускается, настройки и данные не монтируются в LMT. Лимиты памяти: LMT 6 ГБ, LLM 3 ГБ.

Команды установки требуют доступа к ВМ; наличие кода в GitHub само по себе не означает, что sidecar уже установлен. После установки проверяются public status, запрет анонимного запуска и реальная обработка с очисткой и набором, повторное чтение из кэша.

## Проверки

Node-тесты проверяют миграцию старого режима, идентичность кэша, очередь, отмену и контракт готовой страницы. Python-тесты проверяют шифрование, изоляцию владельца, кэш, отмену, повторный запуск и проверку сессии. Browser-тест использует явно синтетическую готовую страницу: проверяет читалку, предобработку, повторное открытие, переключение места обработки и отсутствие маркеров. Это не тест качества моделей.

## Новые варианты для сравнения

Hy-MT2 остаётся базовым профилем качества. Index Translate использует официальный prompt без system message, temperature=0 и выключенное thinking. На ВМ llama.cpp router держит максимум одну переводческую модель в памяти, меняя её при выборе другого профиля.

YOLO26n Manga имеет два класса: text и frame. Только text идёт в OCR/очистку. Дополнительный выбор панелей меняет порядок чтения, не стирает изображение панели. YOLOv12x находит только панели. MAGI detection-only и YOLOv12 работают в отдельном приватном сервисе ВМ; процесс модели завершается до OCR/перевода, чтобы не держать все тяжёлые веса одновременно. Новых публичных портов/OCI ресурсов нет. Для обычной COCO YOLO26m обученные на манге веса пока не найдены; модель не выдаётся за работающий текстовый детектор.

PP-OCRv6 Manga обновлён до v0.2: 1,82 МБ детектор и 21,17 МБ OCR. Его OCR сначала определяет строки, поворачивает вертикальные строки отдельно и сохраняет порядок японских колонок. Это устраняет прежнее распознавание повёрнутого целого пузыря. Результаты на реальных вертикальных страницах нужно оценивать отдельно от печатных smoke-тестов.

Реальные браузерные smoke-тесты на CPU/WASM (не физический Android/GPU): Hy-MT2 Q8 перевёл EN и JP, Index Q4 перевёл те же две реплики. Первый запуск включал локальную передачу/запись весов, проверку SHA, загрузку модели и генерацию: 433,48 с и 240,94 с соответственно. Это **не сравнительный тест скорости генерации**: разные квантизации/веса и холодный кэш. Сохранены точные ответы и условия в `docs/benchmarks/`.
