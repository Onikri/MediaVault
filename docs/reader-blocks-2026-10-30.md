# Пакетный режим «Блоки»

Кнопка с иконкой листа находится в настройках перевода. Режим доступен с
личными ключами Google и с серверными слотами Oracle, включая CBZ из Drive.
Изображения страниц декодируются на устройстве. Быстрый поиск использует
связные компоненты и группировку строк, без скачивания детектора. Для CJK
добавлен проход по вертикальным столбцам. Длинные страницы анализируются
перекрывающимися полосами с масштабом по ширине, а не по общей высоте.

На сервер отправляются PNG-листы текстовых вырезок с ID и координатами листа.
Исходные страницы туда не входят. Размер по умолчанию 1600 × 2264, свободный
низ обрезается; большой блок может увеличить лист. Пиксели букв не уменьшаются.
Количество исходных страниц не фиксируется: ограничиваются площадь, число
областей, память, время подготовки и размер JSON. В одном запросе до трёх
листов, 100 областей и 16 МиБ base64 изображений с запасом под остальной JSON.
Один плотный исходник может потребовать нескольких листов.

Порядок: страницы по очереди, строки сверху вниз, внутри строки слева направо
для вебтуна/манхвы и справа налево для манги. Положение вырезки на листе не
меняет её ID. Ответ проверяется на полноту и уникальность всех ID до очистки.
Неполный ответ не изменяет исходник.

На стыке двух соседних страниц вебтуна алгоритм ищет близкие к краю области
одинаковой ширины с большим горизонтальным перекрытием. Неоднозначные пары
остаются раздельными. Совпавшие фрагменты отправляются одной вырезкой,
переводятся один раз, получают общую высоту вёрстки и одинаковый кегль.
Каждая страница показывает свою часть общего параграфа через clipping.
Это геометрическая эвристика, а не семантическая гарантия. Связи видны в
отладке. Ключ кэша включает хэши соседних страниц.

Алгоритмический поиск может пропускать белый текст, сложный рисунок и короткие
надписи. Панель показывает фактические рамки, количество переведённых областей
и блоки, отвергнутые переводчиком. Количество пропущенного детектором текста
не объявляется измеренным без ручной эталонной разметки: проверять его нужно
сравнением рамок с оригиналом каждой страницы. Другие режимы поиска сохранены.

## Сессии и отображение

Просмотрщик и превью имеют разные ID в рамках вкладки. Повторное открытие
заменяет только сессию того же владельца и просмотрщика. Запоздавший ответ
предыдущей подготовки не может заменить новую главу. Аренда новых сессий —
120 секунд с heartbeat каждые 30 секунд; уход со страницы отправляет DELETE
с keepalive. Ошибка формирования списка ресурсов освобождает созданную сессию.
Старые потребители, включая аудио, сохраняют прежний двухчасовой контракт.

И манга, и манхва используют исходную ширину с уменьшением под экран.
Перевод рисуется отдельным слоем поверх стабильного оригинала; видимость
страницы не пересоздаёт её URL и не перезапускает очистку.

Отладка показывает рамки, фон после очистки, реальный JSON и листы запроса,
очередь и номера слотов ключей. Закрытый `/reader/google/diagnostics` сообщает
наблюдавшиеся стадии и HTTP-коды только текущего владельца. Исходящий IP ВМ
измеряется запросом к ipify без ключей, с кэшем 15 минут. Наличие настройки
ключа отделяется от подтверждённого HTTP 200. При недоступности диагностики
успешный статус или IP не выдумываются.

## Файлы моделей

Папка выбирается через File System Access API; разрешённый handle хранится
в IndexedDB. Cookie с текстовым путём не даёт браузеру доступа к диску.
Пакет включает выбранный детектор и инпейнт, а для локальных Hy-MT2 / Index —
также OCR и GGUF. GGUF читается из выбранной папки без повторной загрузки,
проверяется потоковым SHA-256 и передаётся runtime как Blob. Экспериментальный
WebLLM использует свой кэш браузера. В папку моделей не сохраняются страницы
и API-ключи. Права могут потребовать повторного подтверждения браузером.

## Проверки и внешняя конфигурация

Node-тесты проверяют пакетирование, порядок, ID, пары на стыках, очередь,
изолированные варианты кэша, lifetime сессии и чтение GGUF без скачивания.
Python-тесты проверяют смену глав, владельцев, истечение аренды, очистку при
ошибках, устаревшие подготовки и приватную диагностику.

`node tests/manga-blocks-browser.cjs` выполняет настоящий алгоритмический
поиск, PNG-пакетирование, очистку и набор в Canvas Worker на ширинах 390 и
1366 px: манга, вебтун и разрезанный параграф. Шесть исходных страниц в
фикстуре дают один лист и один запрос. Ответ Google в этих тестах подставной.
Это не проверка качества нейронного перевода, LaMa или локального GGUF-инференса;
новые измерения ML-качества в рамках изменения не проводились.

На существующей ВМ отдельно настроены штатные поля HentaiLib в Suwayomi:
Bearer Token, User ID и срок жизни из переданного пользователем файла.
HentaiLib `/api/auth/me` подтвердил токен HTTP 200; запись настроек проверена
повторным чтением. Секреты не входят в исходники и отчёты. Публикация новых
изменений сайта и серверного кода — отдельный шаг; настройка HentaiLib уже
применена на ВМ.
