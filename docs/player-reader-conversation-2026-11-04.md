# Player, reader and room update — 2026-11-04

## Changes

- Absolute first-pointer timeline seeking, an immediate UI clock update and no duplicate pause-resume prompt. Preview time floats over the full picture; up to120 one-second thumbnails are retained in bounded RAM across hover sessions and cleared on lock.
- Settings show all rows in a two-column grid instead of hidden dot pages. The panel remains attached to its player. A short-screen overflow fallback preserves access to every function rather than clipping controls. Season/episode selection lives at the upper left and the episode browser opens inside the same React player; no video element remount is introduced.
- Stronger reversible showcase depth/zoom. A borderless shared-layout still viewer with zoom, keyboard arrows and fullscreen. The release calendar loads pages progressively, shows the full compact two-column list, and offers a month grid. Real supplied episode names, recap/filler flags and character lists are retained; missing facts are not invented. Watch-order controls distinguish the main continuation line from release order; neither is labelled a universal Fate chronology.
- Reader chapter selection moves to the top. The entire webtoon navigation toolbar is vertical at the right. Reading order and forward gesture direction are independent. The duplicate outer reader header is omitted once its own chrome is ready. Translation controls use the full panel width and explanations collapse behind a button.
- Optional lazy-loaded react-pageflip / StPageFlip paper animation, cover and wide-screen spreads, single-page portrait on phones. Only nearby sheets decode images; translation overlays stay in React. The vendored MIT engine has an explicit cancellable animation-loop lifecycle, because upstream destroy leaves its RAF loop running. Attribution and corresponding source are published.
- An opt-in small-page CPU IllustrationJaNai model uses the existing verified SPAN-S weights and worker. Large pages and translated renders are not downscaled/replaced. Weights are cached once; decrypted page output remains in memory. This is not the grayscale MangaJaNai model and has no promised universal2–3-second runtime.
- Persistent, account-scoped custom avatar in browser storage, available on mobile too. History is grouped by date with cover and resume position. Export/import forms use the existing AniView materials and dense controls.
- Password-room text chat and experimental WebRTC microphone audio. Signalling is limited to authenticated members of that room, voice is opt-in, messages/payloads/rate are bounded. No microphone stream is saved. The normal invitation asks for a password; the QR contains it in a URL fragment and removes it from browser history after joining. The existing bounded video Range/HLS relay remains available. Direct audio across restrictive NATs needs TURN configuration (`roomIceServers`); no cross-country connectivity guarantee is made without those real networks.
- Removed broad500ms room-event suppression, which could swallow a user's immediate Play after buffering/join changes; only matching server-induced events are suppressed.

## Authentication and imports

The preceding deployed recovery release preserved all70 task records and credentials. The30 `waiting_auth` imports no longer consume30 active worker slots. A live refresh still returns Google `invalid_grant` after the user updated browser Drive access; the profile now exposes an explicit **background Drive access on VM** button. No task or file is deleted. YouTube's encrypted session exists, but yt-dlp reports rotated/invalid cookies and the actual Otonoke prepare request still receives a sign-in challenge. New YouTube session consent/cookies are needed; no revoked token is fabricated or silently discarded. Updating yt-dlp alone was not claimed as a login fix.

Avatar persistence, page-flip DOM/interaction and production showcase geometry are checked at mobile and desktop widths.
