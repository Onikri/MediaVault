# Libre Manga Translator в MediaVault 5.6

Встроен web-port [mrdhnto/libre-manga-translator](https://github.com/mrdhnto/libre-manga-translator),
commit `39a95be1890e2ea3e227052976bbaf576a8eb7b3` (1.0.3).
Это настоящие upstream-модули detection → script gate → OCR → translation →
inpaint → typesetting. Старый Oracle-перевод доступен отдельно.

## Запуск

Открой главу → настройки читалки → «Libre Manga Translator · модели и режим».
Выбери переводчик LMT, исходный язык и режим. Разреши загрузку моделей, затем
нажми «Перевести на русский · LMT». Оригинальный CBZ в Drive не меняется.
Кнопка «Оригинал» возвращает исходную страницу; маркеры позволяют прочитать
полную реплику и сверить её с оригиналом.

| Режим | Где выполняется работа | Требования |
| --- | --- | --- |
| Локально · WebGPU | detection/OCR/inpaint/typesetting в браузере; LLM на WebGPU | Chrome/Edge и доступный WebGPU, достаточно памяти. Некоторые ONNX-модели выполняются на WASM CPU из-за неподдерживаемых GPU-операторов |
| Свой LLM-сервер | Изображения остаются в браузере, распознанный текст отправляется на указанный сервер | OpenAI-compatible `POST <base>/chat/completions`, CORS для `https://onikri.github.io`; имя модели, например локальная модель Ollama/LM Studio |
| Oracle | Прежний EN→RU pipeline на существующем сервере | Профиль владельца и подключённый сервер |

Новый LLM на Oracle автоматически не устанавливается. ARM 2 OCPU/12 ГБ без GPU
не подходит для обещания быстрого LLM-перевода. Платные API не подключаются.
В собственном серверном режиме укажи базовый URL вида `https://your-host/v1`.
Удалённый HTTP и URL со встроенными логином/паролем запрещены; loopback HTTP
может дополнительно блокироваться браузером на HTTPS-сайте. Закрытые API с
обязательной API-key авторизацией этим адаптером пока не поддерживаются.

Доступны RT-DETR и ComicTextDetector, PaddleOCR, японские PP-OCRv6/Manga-OCR,
корейский Pororo; Fast fill/denoise/Telea и LaMa. Специализированный OCR нельзя
случайно запустить для другого языка. Модели WebLLM: Llama 3.2 1B и Qwen 3.5
0.8B/2B/4B; FP32-варианты 1B/0.8B подходят GPU без shader-f16, но занимают больше
памяти. Наличие `navigator.gpu` не гарантирует совместимость конкретной модели.

Модели загружаются только при включённом переводе после явного разрешения.
LLM-веса могут занимать гигабайты; OCR и LaMa скачиваются отдельно. Upstream
кэширует веса через CacheStorage. Браузер может очистить этот кэш, особенно на
телефоне. Не включай загрузку впервые на ограниченном мобильном трафике.
Закрытие читалки, блокировка библиотеки или отмена активной страницы завершают
iframe вместе с inference и его GPU-ресурсами. Следующая страница может заново
инициализировать сессии из кэша. Последние пять готовых страниц хранятся в памяти
читалки и повторно не переводятся при возврате; на диск этот кэш не записывается.
Во время загрузки LLM виден процент подготовки. Очередь последовательная; контекст реплик
сохраняется в памяти движка отдельно по произведениям, до закрытия движка.

## Сборка и лицензии

`npm run build` собирает основное приложение и отдельный `dist/lmt/index.html`.
Engine запускается лениво в same-origin iframe, IPC через MessageChannel
передаёт расшифрованный Blob страницы и результат; Google-токены и ключ
библиотеки не передаются. WASM runtime размещён рядом, один поток позволяет
работать на GitHub Pages без COOP/COEP. Не нужен отдельный платный хостинг.

Каталог `lmt/` — AGPL-3.0-or-later, полная лицензия в `lmt/upstream/LICENSE`.
Соответствующий исходный код и изменения доступны в этом репозитории; ссылки
на источник и лицензию видны в настройках. `lmt/upstream/UPSTREAM.txt` фиксирует
оригинальный commit. Изменены web runtime/storage bindings, таймаут своего
сервера, список FP32 моделей и перенос длинных русских слов. Используются
ONNX Runtime Web (MIT), WebLLM (Apache-2.0), их зависимости и отдельные лицензии
скачиваемых моделей. Все модели не включаются в Pages-артефакт.

## Что проверено

- Реальные ONNX RT-DETR, script gate и английский PaddleOCR на неэротической
  EN-странице; Fast inpaint и набор результата. Для настоящего перевода в этой
  проверке использована локальная Argos EN→RU через совместимый тестовый endpoint.
  Это подтверждает цепочку, но не качество WebLLM на физическом GPU.
- Отдельный контрольный тест с фиксированным переводом проверяет контракт API.
- `test:lmt`: реальные preflight-ограничения engine до загрузок, затем fixture
  проверяет MessageChannel, progress, transferable image, отмену, повторный
  запуск и освобождение при блокировке. Fixture не считается ML-инференсом.
- JP/KR OCR, LaMa и локальные WebLLM-модели подключены к upstream pipeline;
  реальная проверка на физических desktop/Android GPU ещё нужна. Эти варианты
  не объявляются одинаково быстрыми и качественными на всех устройствах.
