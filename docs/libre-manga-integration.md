# Libre Manga Translator в MediaVault 5.6

Встроен web-port [mrdhnto/libre-manga-translator](https://github.com/mrdhnto/libre-manga-translator),
commit `39a95be1890e2ea3e227052976bbaf576a8eb7b3` (1.0.3).
Это настоящие upstream-модули detection → script gate → OCR → translation →
inpaint → typesetting. Старый Oracle-перевод доступен отдельно.

## Запуск

Открой главу → настройки читалки → «Libre Manga Translator · модели и режим».
Выбери переводчик LMT, исходный язык и режим. Разреши загрузку моделей, затем
нажми «Перевести на русский · LMT». Оригинальный CBZ в Drive не меняется.
Кнопка «Оригинал» возвращает исходную страницу; маркеры позволяют прочитать
полную реплику и сверить её с оригиналом.

| Режим | Где выполняется работа | Требования |
| --- | --- | --- |
| Локально · WebGPU | detection/OCR/inpaint/typesetting в браузере; LLM на WebGPU | Chrome/Edge и доступный WebGPU, достаточно памяти. Некоторые ONNX-модели выполняются на WASM CPU из-за неподдерживаемых GPU-операторов |
| Свой LLM-сервер · текст | Изображения остаются в браузере, распознанный текст отправляется на указанный сервер | OpenAI-compatible `POST <base>/chat/completions`, CORS для `https://onikri.github.io`; имя модели, например локальная модель Ollama/LM Studio |
| Свой VLM-сервер · изображение | Размеченная страница передаётся vision-модели; OCR пропускается | OpenAI-compatible vision endpoint и поддерживающая изображения модель |
| Oracle | Прежний EN→RU pipeline на существующем сервере | Профиль владельца и подключённый сервер |

Новый LLM на Oracle автоматически не устанавливается. ARM 2 OCPU/12 ГБ без GPU
не подходит для обещания быстрого LLM-перевода. Платные API не подключаются.
В собственном серверном режиме укажи базовый URL вида `https://your-host/v1`.
Удалённый HTTP и URL со встроенными логином/паролем запрещены; loopback HTTP
может дополнительно блокироваться браузером на HTTPS-сайте. Для закрытого своего endpoint можно указать Bearer API key: он остаётся только
в памяти вкладки и не сохраняется в localStorage.

Доступны RT-DETR и ComicTextDetector, PaddleOCR, японские PP-OCRv6/Manga-OCR,
корейский Pororo; Fast fill/denoise/Telea и LaMa. Специализированный OCR нельзя
случайно запустить для другого языка. Модели WebLLM: Qwen 3.5 4B (приоритет качества), 2B и 0.8B (экономные
сравнения). FP32-варианты подходят GPU без shader-f16, но занимают больше памяти. Наличие `navigator.gpu` не гарантирует совместимость конкретной модели.

Модели загружаются только при включённом переводе после явного разрешения.
LLM-веса могут занимать гигабайты; OCR и LaMa скачиваются отдельно. Upstream
кэширует веса через CacheStorage. Браузер может очистить этот кэш, особенно на
телефоне. Не включай загрузку впервые на ограниченном мобильном трафике.
Закрытие читалки, блокировка библиотеки или отмена активной страницы завершают
iframe вместе с inference и его GPU-ресурсами. Следующая страница может заново
инициализировать сессии из кэша. Последние пять готовых страниц хранятся в памяти
читалки и повторно не переводятся при возврате; на диск этот кэш не записывается.
Во время загрузки LLM виден процент подготовки. Очередь последовательная; контекст реплик
сохраняется в памяти движка отдельно по произведениям, до закрытия движка.

## Сборка и лицензии

`npm run build` собирает основное приложение и отдельный `dist/lmt/index.html`.
Engine запускается лениво в same-origin iframe, IPC через MessageChannel
передаёт расшифрованный Blob страницы и результат; Google-токены и ключ
библиотеки не передаются. WASM runtime размещён рядом, один поток позволяет
работать на GitHub Pages без COOP/COEP. Не нужен отдельный платный хостинг.

Каталог `lmt/` — AGPL-3.0-or-later, полная лицензия в `lmt/upstream/LICENSE`.
Соответствующий исходный код и изменения доступны в этом репозитории; ссылки
на источник и лицензию видны в настройках. `lmt/upstream/UPSTREAM.txt` фиксирует
оригинальный commit. Изменены web runtime/storage bindings, таймаут своего
сервера, список FP32 моделей и перенос длинных русских слов. Используются
ONNX Runtime Web (MIT), WebLLM (Apache-2.0), их зависимости и отдельные лицензии
скачиваемых моделей. Все модели не включаются в Pages-артефакт.

## Что проверено

- Реальные ONNX RT-DETR, script gate и английский PaddleOCR на неэротической
  EN-странице; Fast inpaint и набор результата. Для настоящего перевода в этой
  проверке использована локальная Argos EN→RU через совместимый тестовый endpoint.
  Это подтверждает цепочку, но не качество WebLLM на физическом GPU.
- Отдельный контрольный тест с фиксированным переводом проверяет контракт API.
- `test:lmt`: реальные preflight-ограничения engine до загрузок, затем fixture
  проверяет MessageChannel, progress, transferable image, отмену, повторный
  запуск и освобождение при блокировке. Fixture не считается ML-инференсом.
- JP/KR OCR, LaMa и локальные WebLLM-модели подключены к upstream pipeline;
  реальная проверка на физических desktop/Android GPU ещё нужна. Эти варианты
  не объявляются одинаково быстрыми и качественными на всех устройствах.

## Качество: профиль 5.6.1

В качестве исходной локальной модели предлагается Qwen3.5-4B. Llama 1B убрана
из интерфейса. Qwen 2B/0.8B оставлены явно подписанными компромиссными режимами
для сравнений и малой памяти; их результат не объявляется равным 4B. Gemma не
добавлена автоматически: upstream прямо отключил её из-за проблем sliding-window
attention. Для неизвестной видеокарты нельзя обещать, что 4B поместится в память.

Автоматический OCR выбирает PP-OCRv6 Manga для японского, новый PP-OCRv5 Korean
для корейского, PaddleOCR для английского/китайского. Корейские ONNX-веса закреплены
на HF commit `407d31ecdc555de8282c578889774861eea2667e`, SHA256 проверяется до
сессии. Реальный размер — 13 401 252 байта, словарь 11 945 символов, включая
все **11 172** слога хангыль; выход модели 11 947 классов (blank + dict + space).
Хотя README/config конвертера сообщает height=32, проверка ONNX graph показала
**48**, поэтому используется 48. Иначе модель получает несовместимый тензор.
Источник: https://huggingface.co/monkt/paddleocr-onnx . Исходная архитектура/словарь
PaddleOCR — Apache-2.0. Два собственных печатных корейских предложения прочитаны
реальным ONNX в Chromium/WASM; это smoke test, не репрезентативный манхва-benchmark.

В режиме своего сервера появился **VLM · страница с визуальным контекстом**:
после детектора вся страница размечается пронумерованными рамками и передаётся
в OpenAI-compatible vision endpoint. Браузерный OCR и Script Gate пропускаются,
модуль WebLLM не загружается. Сервер видит изображение, поэтому режим обозначен
отдельно от отправки только текста. Подходящие семейства: Qwen-VL/InternVL;
нужна реально запущенная vision-модель, одного имени в настройках недостаточно.
Платный Gemini не используется. Локальный API-клиент не устанавливает VLM на VM.

Ответ VLM содержит явные `id`, оригинал и русский перевод. Проверяются количество,
полнота, типы и уникальность номеров; переставленные элементы сортируются по ID,
ошибочный ответ не затирает рисунок. В текстовом/WebLLM режиме после коррекции
число переводов тоже проверяется строго: пропущенные реплики не маскируются
подстановкой пустых элементов. Межстраничный контекст сохраняется отдельно по тайтлам.

### Что в предложенных заменах требует поправки

- Текущая LaMa уже **manga**: `ogkalu/lama-manga-onnx-dynamic`, Apache-2.0,
  206 291 843 байта. Она не заменяется случайным фото-чекпоинтом по возрасту модели.
- Доступный проверенный MI-GAN ONNX pipeline — 28 079 181 байт (MIT), а не «менее
  10 МБ». Найденные официальные веса не заявлены как дообученные на манге.
  Он пока не включён как якобы более качественный manga-redraw без сравнения масок
  и скринтонов. Источник: https://huggingface.co/andraniksargsyan/migan .
- Для YOLO11-seg недостаточно взять COCO-веса: нужны подтверждённые manga-классы
  и соответствующая сегментация. Встроенный RT-DETR сохраняется; 5–8-кратное
  ускорение и лучшая точность на этой VM пока не измерены.

### Замеры Oracle

`deploy/oracle/benchmark-lmt.py` запускается внутри существующего importer без
импорта `api`/TaskStore и изменения очереди. Сравнивает прежний OCR/Argos и
настоящий LMT на одном уже опубликованном коротком фрагменте, с хешем выборки,
первым/повторным проходом, временами стадий и приблизительным RSS дерева процессов.
Argos прогревается одинаково для сравнений; его время загрузки выводится отдельно.
Прежний pipeline возвращает слои, LMT также рисует готовую страницу, поэтому
общий коэффициент «во столько раз быстрее» некорректен без учёта стадий.

`--vision-url http://127.0.0.1:PORT/v1 --vision-model MODEL` добавляет реальный
запрос к установленной на VM VLM. Скрипт не скачивает и не устанавливает большие
LLM самостоятельно. Без этого параметра отчёт явно содержит `visionTested:false`.
Замер на локальном компьютере или fixture-ответ не выдаётся за Oracle-замер.

Локальный smoke test PP-OCRv5 Korean (не Oracle): 2 собственные печатные строки,
10 997 мс первая инициализация, 704 мс повторный inference; буквы прочитаны
верно, пропущены один пробел и конечная точка. ONNX/WASM, реальные веса из
локально скачанного кэша; сетевую скорость и всю манхву эти числа не характеризуют.

### Контрольный результат на одинаковом фрагменте (локально, не Oracle)

[Полный JSON](benchmarks/lmt-local-2026-10-25.json) содержит хеш входа,
все распознанные реплики, перевод и времена стадий. Argos заранее прогрет
для обоих вариантов; реальные ONNX-веса поданы из скачанного кэша.

| Алгоритм | Первый профильный проход | Повторный | Качество на этом фрагменте |
| --- | ---: | ---: | --- |
| Текущий серверный Tesseract + refined bubbles + Argos, запущенный локально | 2,84 с | 2,65 с | Две основные реплики прочитаны и переведены |
| Browser LMT RT-DETR + Paddle + тот же Argos + inpaint/typeset | 53,51 с | 9,97 с | Нашёл 3 области; первая реплика распознана хуже, появились ложные фрагменты |

Это показывает, почему новый pipeline не назначен лучшим только по названию:
на этом фрагменте текущий серверный алгоритм лучше. Он остаётся исходным
режимом; LMT и VLM включаются явно для сравнения. Результат не характеризует
всю мангу, японский/корейский или WebGPU. Реальная VLM в этом тесте не
запускалась (`visionTested:false`). Oracle ARM ещё требует отдельного запуска.
