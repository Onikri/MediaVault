# Перенос источников Suwayomi в MediaVault

Объём переноса фиксирует [реестр установленных источников](native-source-inventory.csv). Единица проверки — ID источника в Suwayomi. Один APK может содержать несколько языков, сайтов или режимов одного сайта с разными ID. Сохраняем ID в фильтрах, выдаче, каталоге и сохранённых ссылках.

## Порядок работ

1. Снять инвентарь на Oracle через REST API и GraphQL. Сохранить пакет, версию, языковой вариант, ID, настройки и японский маршрут. Сверять каждый следующий снимок с исходным, чтобы обновление или удаление APK не стерло работу из реестра.
2. Сопоставить каждый пакет с кодом той версии, которая установлена. Определить общий движок, переопределённые запросы и разбор, учётные данные, платные главы, специфические картинки и ограничения маршрутизации. Сопоставление использует фактическое имя APK из Gradle, включая `pkgName` после переезда модуля, и сумму версии расширения и общего движка. Для исчезнувших из основной ветки исходников сохраняем [ревизии из истории](native-source-history.json). Колонка `overrides` помогает найти явные переопределения в Kotlin-модуле. Конфигурация, унаследованные методы и код с исторических ревизий требуют отдельного разбора.
3. Переносить код партиями по 50 установленных APK из реестра. Языковые профили одного APK входят в ту же партию и учитываются отдельно от размера партии. Внутри партии объединять пакеты с общим движком, сохранять переопределения и подключать прямые адаптеры к поиску, индексации, просмотру и скачиванию. Для нестандартных протоколов добавить индивидуальные адаптеры. Закрытые и пользовательские источники проверять с их собственной конфигурацией; отдельно фиксировать причину, когда для живой проверки нет доступа.
4. После внесения кода всей партии один раз запускать релевантные Python- и Node-тесты и продакшен-сборку. При конкретном сбое повторять затронутую проверку. После этапа переноса проводить пакетные прогоны на Oracle. Протокол, пагинацию, фильтры, чтение, скачивание и сохранённые ссылки проверять на контрольных источниках каждого семейства. Добавлять контрольный источник для каждого отличающегося маршрута, способа доступа и формата данных. Отдельно разбирать расхождения и повторять временные ошибки по их ID. Серии замеров p50/p95 выполнять на контрольной выборке при изменениях, влияющих на скорость.
5. Выпускать проверенные группы на Oracle из main по правилам [координации выкладки](deploy-coordination.md). Сохранить каталог, позиции очереди, список расширений, маршруты и доступ к старым ссылкам. Убирать зависимость от Suwayomi по каждому источнику после сверки прямого маршрута и ссылок на ранее сохранённые главы.
6. Завершить миграцию после сверки с текущим инвентарём, проверки всех применимых операций для всех ID и подтверждения, что обычные поиск, индексация, чтение и скачивание больше не обращаются к Suwayomi. Источники с блокерами остаются отдельными строками с указанием причины и невыполненных проверок.

## Статусы и проверка охвата

- `pending` — перенос или проверка ещё не начаты.
- `implemented` — прямой код проверен локально, живая сверка ещё не закончена.
- `verified` — операция сверена на Oracle для этого ID.
- `blocked` — проверка упёрлась во внешнюю зависимость, причина записана в журнале миграции.
- `not_applicable` — операция отсутствует в самом источнике, причина записана в журнале миграции.

Статус хранится отдельно для поиска, каталога, метаданных, глав, страниц, CBZ и старых ссылок. Прохождение одной операции не меняет статусы остальных. Привязка исходников снимка — [Keiyoushi 6f345a8](https://github.com/keiyoushi/extensions-source/tree/6f345a81459739e35d8fc94c05455464e856f771).

В очереди поиска прямые адаптеры получают приоритет внутри выбранного языка. При смене маршрута сбрасываются история сетевых отказов и кэш запросов затронутых ID, а каталог остаётся доступен для начальной выдачи.

Снимок Oracle от 15 ноября 2026 года включает 725 APK и 1 640 вариантов. Для каждого варианта найден каталог исходников с совпадающей версией. После обновления APK генератор сбрасывает статусы его варианта и сообщает, если уже учтённый ID исчез из нового снимка.

Обновление реестра из локального снимка и архива исходников:

```powershell
. .\scripts\cache-env.ps1
python scripts/build-source-migration-register.py .codex-local/extension-audit-results/inventory.json .codex-local/upstream/keiyoushi-6f345a814597.tar.gz docs/native-source-inventory.csv
```

Ключ `--require-complete` завершает проверку ошибкой, если ещё есть хотя бы одна операция без `verified` или обоснованного `not_applicable`. Результаты отдельных живых прогонов находятся в [журнале проверки](native-source-verification.md).

## Пакетная проверка

Реестр хранит статус по каждому профилю и операции. В отчёте о партии указываются число APK и отдельно число их профилей. Операции отмечаются как `implemented` после локальной проверки партии. Живой прогон на Oracle идёт после переноса. Он проверяет каталог, поиск и оглавление, а проверки чтения и скачивания выполняются для отличающихся вариантов протокола. Сетевые расхождения повторяются по затронутым ID.

Скрипт [probe-native-source-batch.py](../scripts/probe-native-source-batch.py) проверяет первые страницы прямых каталогов и принадлежность карточек исходному ID. Ключ `--search` добавляет поиск одной возвращённой карточки по тому же ID. Ключ `--chapters` проверяет ID и оглавление той же карточки, включая адрес каждой главы. Варианты одного хоста идут последовательно. Разные хосты проверяются параллельно. После HTTP 429 оставшиеся варианты этого хоста откладываются. Каждый результат записывается отдельной строкой JSON.

```powershell
. .\scripts\cache-env.ps1
python scripts/probe-native-source-batch.py --ssh mediavault-vm --inactive --batch-size 200 --workers 8 --search --chapters |
    Tee-Object -FilePath .codex-local/native-probe-batch.jsonl
```

По умолчанию скрипт начинает с профилей, которые ещё предстоит подключить. Ключ `--inactive` оставляет в прогоне только эти профили. Ключ `--offset` выбирает следующую пачку, а `--source` позволяет повторить конкретные ID. Поля `catalogue`, `search` и `chapters` относятся к отдельным операциям пакетного прогона. Если поиск не вернул точную карточку, оглавление всё равно проверяется по ссылке из каталога. Чтение, CBZ и сохранённые ссылки подтверждаются отдельными проверками в реестре.

## Madara

В реестре 105 пакетов семейства Madara, включая архивный Anisa Scans. У 11 пакетов в Kotlin-модулях нет явных переопределений. Они подходят для первой проверки общего движка. Для остальных пакетов работаем по `overrides` и исходникам. Отдельно сверяем варианты Madara и MadaraNoAjax, выдачу через `madara_load_more`, HTML-каталог, способ загрузки списка глав, порядок страниц, переопределения URL и заголовков. При сравнении нужны образцы с целым и дробным номером главы, с пагинацией каталога и с несколькими жанрами.

Для 89 из 109 вариантов заведены [профили](../server/manga_madara_profiles.py) с точными ID, доменами, маршрутами, режимом глав, селекторами и форматами дат. В рабочей ветке подключены 13 профилей с живой проверкой поиска, чтения и скачивания. Остальные профили остаются на Suwayomi до проверки соответствующих операций.

Ссылки MangaForFree, ManhwaClub и двух ID на mangafree.info сохраняют выбранный ID источника. Внешнему серверу передаётся исходный URL. Варианты MangaForFree и ManhwaClub воспроизводят правила отбора оригинальных глав из расширений.

## MangaThemesia

В реестре 23 варианта. Для 14 добавлен [прямой адаптер](../server/manga_themesia.py) с каталогом, справочником жанров, карточкой и читалкой. Активированы Lagoon Scans, Akaza Scans, Violet Scans и Aster Scans. Для сохранённых глав с URL вне каталога адаптер сверяет родительский тайтл по ссылке на странице читалки.

Остаются варианты с собственной выдачей, закрытыми главами и отдельным движком MangaThemesiaAlt. Для них сохраняются существующие маршруты.

## Iken

Все восемь установленных ID подключены в рабочей ветке через [прямой адаптер](../server/manga_iken.py). Сохраняются размер страницы Sana, сортировка изображений Sana и Magus, заголовок кэша Hive и отдельные списки новелл Vortex и Nyx. Проверяется принадлежность ID главы тайтлу. Если один URL соответствует нескольким ID, читалка и сохранённые ссылки различают их.

## MangaCatalog

Для всех 13 ID заведены [прямые каталоги](../server/manga_mangacatalog.py) по точным установленным версиям. Поиск по названиям и оригинальным слагам работает в памяти. Разные издания имеют разные пути и ID, а повторные названия по одному пути сохраняются как синонимы. Девять ID активированы в рабочей ветке после сравнения чтения, CBZ и сохранённой ссылки на Oracle.

## Keyoapp

Для всех 16 установленных ID добавлены профили [прямого адаптера](../server/manga_keyoapp.py). Исходная версия использует публичный каталог `/series/`, Keyoapp V2 — AJAX-поиск и список глав, переработанный шаблон — `/search` и HTML со списком страниц. В рабочей ветке подключены девять ID после проверки поиска, глав, чтения, скачивания и старых ссылок.

## VineTheme

Для семи установленных ID заведены профили [прямого адаптера](../server/manga_vinetheme.py). Каталог читает JSON, а карточки и главы читают данные React Flight. Жанры и теги используют разные параметры фильтра. Старые записи, которые содержат только внутренний ID, сопоставляются с тем же ID в данных исходного сайта. В рабочей ветке подключены четыре ID после живой проверки на Oracle.

## HentaiHand

[Прямой адаптер](../server/manga_hentaihand.py) содержит 34 установленных варианта HentaiHand и 19 вариантов nHentai.com. Сохраняет исходные языковые фильтры, одну главу на тайтл и служебный ID выбранного источника в ссылках. Текущий маршрут Suwayomi используется до проверки живого чтения, CBZ, сохранённых ссылок и совместимости фильтров.

## Comici Viewer

[Адаптер](../server/manga_comici.py) содержит все 29 установленных профилей. Он читает рейтинг, списки и поиск, получает статус доступа к каждой главе и собирает плитки открытой страницы для читалки и CBZ. Запросы к издательским доменам используют существующий японский шлюз Oracle по серверной конфигурации. Comic Pash, Hana To Yume+ и Champion Cross подключены в рабочей ветке после сквозной проверки. Для Comic Growl домен внесён в конфигурацию следующей выкладки шлюза.

## GigaViewer

[Адаптер](../server/manga_gigaviewer.py) содержит 19 установленных издателей. Для индекса он обходит коллекции из установленных расширений, включая отдельные HTML-разделы Shonen Jump+ и Sunday Web Every. В фильтры жанров попадают только издательские группы `Genre`. Главы и тома загружаются с сохранением статуса доступности. Comic Action, Shonen Jump+, Comic Days и Comic Gardo подключены в рабочей ветке после проверки старых ссылок, чтения и CBZ.

## YiiManga и YiiMadara

[Общий адаптер](../server/manga_yii.py) содержит все 22 установленных профиля. Он воспроизводит маршруты каталогов, варианты поиска, отбор оригинальных изданий по языку и особые маршруты отдельных сайтов. Каталог и оглавление проверены на Oracle. Чтение и старые ссылки проверены на тестовых данных, рабочие маршруты этих источников пока обслуживает Suwayomi.
