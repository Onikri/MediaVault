# Автоматический импорт на собственной бесплатной VM

Статус: код для самостоятельного развёртывания. Пока VM и OAuth не настроены,
`importServerUrl` в `config.js` пустой, сайт использует прежний ручной Colab.
Этот документ не означает, что VM уже создана или что живые источники проверены.

## Что получает пользователь

Поиск параллельно запрашивает Shikimori, AnimeGO и AnimeVost. Карточки Shikimori
содержат обложку, оценку, название; после выбора загружается описание и ищется
оригинальное название. Кандидаты источников показаны отдельно: одинаковое
название не гарантирует одинаковый сезон. Пользователь выбирает фактическую
страницу, сезон, серии, качество и нажимает «Добавить в библиотеку».

API сохраняет задание; независимая служба скачивает, собирает MP4, шифрует и
пишет в Drive. Видео не идёт через устройство пользователя. Для просмотра
трафик Drive → устройство, конечно, нужен. Вкладку можно закрыть. На открытой
странице очередь обновляется каждые пять секунд и каталог обновляется по мере
сохранения. После перезапуска VM незавершённое задание запускается повторно;
завершённые серии пропускаются по существующим манифестам. Незавершённая серия
скачивается заново. Ошибки доступа/квоты не вызывают бесконечных платных повторов:
задание останавливается, повторный импорт запускает владелец.

## Бесплатность — обязательная граница

Подходящий кандидат — Oracle Cloud Always Free VM, **только если консоль твоего
аккаунта и региона подтверждает бесплатность выбранных ресурсов**. Регистрация
и проверка карты выполняются самим владельцем. Доступность мощностей,
региональные условия и квоты меняются; код не гарантирует получение VM.

- Не переходи на Pay As You Go и не выбирай ресурсы, бесплатные только на время trial.
- До создания проверь отметку Always Free для VM, образа, дисков и используемой сети,
  а также условия исходящего трафика и адреса. Если бесплатность не подтверждена — не создавай.
- Не включай платные GPU, балансировщик, NAT gateway, платные snapshots, managed DB,
  дополнительный диск или автоматическое масштабирование. Они этому приложению не нужны.
- Используй один сервер, один worker и только уже выделенный бесплатный диск.
  Нужны Linux, Python 3.10+, ffmpeg, минимум 2 ГБ RAM и 5 ГБ свободного временного места.
- Бесплатный поддомен, например зарегистрированный у DNS-провайдера, может заменить
  покупку домена; сертификат Let's Encrypt бесплатен.
- Следи за квотой трафика провайдера и свободным Drive. Бюджетные уведомления сами
  по себе НЕ являются запретом списаний. Ограничения приложения не заменяют ограничения
  облачного аккаунта. При исчерпании бесплатной квоты останови worker.

Установщик не вызывает облачные API, не создаёт ресурсы, не подключает оплату
и не увеличивает квоты. Создание аккаунта и VM — обязательные внешние шаги.

## Развёртывание

На уже созданной бесплатной Ubuntu VM:

```sh
git clone https://github.com/Onikri/MediaVault.git
cd MediaVault
sudo bash deploy/install.sh
```

Для проверки ветки до merge сначала переключись на `codex/automatic-server-import`.

В `/etc/mediavault.env` указан **публичный Web Client ID сайта**, не Desktop client
из следующего шага. API сверяет аудиторию входящего токена и подтверждённый email
владельца. Импорт доступен только владельцу, определённому в `server/vault_drive.py`.
Origin должен быть ровно `https://onikri.github.io`, без `/MediaVault/`.

Привяжи свой DNS hostname к публичному адресу VM. Скопируй
`deploy/nginx.conf.example` в `/etc/nginx/sites-available/mediavault`, замени
`import.example.com` своим hostname, включи конфигурацию:

```sh
sudo ln -s /etc/nginx/sites-available/mediavault /etc/nginx/sites-enabled/mediavault
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d YOUR_HOSTNAME --redirect
```

В сетевых правилах разреши 80/443; SSH — только со своего адреса.
8090 должен оставаться на loopback, порт 8765 наружу не открывай.
Проверь `https://YOUR_HOSTNAME/health` и автоматическое продление сертификата.

## Однократное подключение Google Drive

1. В своём Google Cloud проекте включи Drive API и создай OAuth client типа
   **Desktop app** для серверной авторизации. Скачай JSON, сохрани его вне Git и
   передай на VM по SSH в файл, доступный только пользователю `mediavault`.
   JSON приложения не является ключом service account; нужен обычный аккаунт владельца.
2. С компьютера открой SSH tunnel:
   `ssh -L 8765:127.0.0.1:8765 USER@VM_ADDRESS`.
3. В этом SSH-сеансе запусти:

```sh
sudo -u mediavault env MEDIAVAULT_DATA=/var/lib/mediavault \
  /opt/mediavault/.venv/bin/python /opt/mediavault/server/setup_runtime.py \
  --client /var/lib/mediavault/oauth-client.json
```

4. Открой выведенную ссылку Google на своём компьютере, авторизуй владельца и
   разреши доступ. Callback пройдёт через tunnel. Токены не выводятся в терминал;
   OAuth credentials сохраняются зашифрованными в приватном каталоге VM.
5. Удали исходный `oauth-client.json` после успешной настройки. Скрипт проверки
   аккаунта отклоняет пользователя, не совпадающего с владельцем библиотеки.

**Google OAuth в режиме Testing:** для Drive refresh token обычно истекает через
семь дней. Для длительной автоматической работы настрой подходящий production
consent screen в соответствии с требованиями Google. Верификация и ограничения
зависят от типа приложения и scopes. Нельзя обещать вечную авторизацию: отзыв
доступа, политика аккаунта и изменения Google могут потребовать повторного входа.

## Включение на сайте

После проверки HTTPS запиши `https://YOUR_HOSTNAME` в `importServerUrl` файла
`config.js`, опубликуй сайт. Не используй адрес чужого сервера: он получит доступ
к библиотеке. Открой библиотеку владельца, перейди в «Импорт», один раз введи
фразу для подключения VM. Сервер проверит фразу и сохранит **производный ключ**
в зашифрованном виде; саму фразу не сохраняет. Теперь импорт запускается с сайта.

Временный access token сайта используется только для проверки личности в Google,
не кладётся в очередь и не заменяет серверный refresh token. Источникам видео
Google credentials не передаются. Ключ VM (`master.key`) и SQLite находятся в
`/var/lib/mediavault`, права каталога 0700, файлов 0600. Компрометация этой VM
даёт доступ к серверным ключам: шифрование на диске не защищает от администратора
самой VM. Удалить сохранённый ключ можно кнопкой на странице после остановки заданий.
Для отзыва доступа к Drive отзови OAuth grant в Google и повтори настройку при необходимости.

## Эксплуатация и ограничения

```sh
sudo systemctl status mediavault-api mediavault-worker
sudo journalctl -u mediavault-api -u mediavault-worker --since today
sudo systemctl stop mediavault-worker  # прекращение фонового импорта
```

- Очередь содержит не более 20 активных заданий. API принимает не более 32 КиБ JSON,
  поиск ограничен 20 запросами в минуту, кэшируется на пять минут, имеет не более
  двух одновременных запросов. Metadata-клиент отдельно ограничивает частоту Shikimori.
- По умолчанию одна серия ограничена 2 ГиБ входного медиа, включая сумму HLS-сегментов.
  Worker использует одну CPU и до 1 ГБ RAM, API до 512 МБ. Это технические ограничения,
  а не гарантия бесплатного облачного биллинга.
- Отмена проверяется между сериями и на этапах обработки. Текущий сетевой запрос
  или ffmpeg может завершиться перед отменой. Уже записанные серии не удаляются.
- Все задания выполняются последовательно. Сайт проверяет очередь перед локальной
  загрузкой и перечитывает каталог. Это не распределённая транзакция: не начинай
  импорт на одном устройстве одновременно с загрузкой на другом. Существующий
  формат Drive-каталога не предоставляет надёжной атомарной блокировки.
- Карточки не подтверждают доступность видео. Обход CAPTCHA, DRM и платного доступа
  не добавлен. Озвучки пока выбираются через конкретную найденную страницу/плеер;
  отдельного универсального списка озвучек нет.
- Поисковые адаптеры AnimeGO и AnimeVost проверяются HTML-фикстурами; доступность
  живых сайтов, актуальные домены и разметку нужно проверить из выбранной VM.
  Они заданы в `server/catalog_search.py`. Смена зеркала требует обновления этого
  доверенного списка. Не создавай открытый proxy для произвольных URL.
- Runtime использует отдельный клиент для API Shikimori. Запрет anime API в
  существующем парсере видео остаётся: он обрабатывает публичный HTML и плееры.
- Обложки/описания показаны в поиске; текущий зашифрованный каталог хранит названия
  импортированных файлов и тайтлов, а не полную копию metadata Shikimori.

Проверки: `pip install -r server/requirements-runtime.txt`, `npm test`,
`npm run test:server`, `npm run test:notebook`, `npm run build`,
`npm run test:automatic`, существующие `test:ui` и `test:browser`.
Тестовые Google, сайты и Drive подменены. Реальный OAuth и импорт с VM проверяются
после регистрации аккаунта, настройки сети и доступа владельца.
