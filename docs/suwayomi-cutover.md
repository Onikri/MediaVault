# Отключение Suwayomi: замеры, пилот и порядок переключения

Документ ведёт агент E плана вывода Suwayomi (17 ноября 2026 года). Он фиксирует исходные замеры до переключения, пилотные сравнения двух путей, порядок переключения партий с откатом и шаги остановки. Перенос кода описан в [реестре](native-source-migration.md), живые проверки — в [журнале](native-source-verification.md). Выкладка идёт по правилам [координации](deploy-coordination.md).

Останавливать, отключать или удалять Suwayomi, его данные и APK может только агент E. Каждый шаг раздела «Остановка» выполняется после отдельного подтверждения владельца в чате.

## Инструменты

| Что | Как |
| --- | --- |
| Счётчик вызовов Suwayomi | Каждый HTTP-запрос к Suwayomi проходит через `suwayomi_bridge.Client.get` и считается по операции, ID источника и исходу. Раз в минуту и при выходе процесса агрегаты дописываются строкой в `DATA_DIR/suwayomi-calls.jsonl` (ротация на 8 МБ в `.1`). Значение ключа `операция\|источник\|исход` — `[вызовы, сумма мс, максимум мс]`. Поле `process`: `api` для uvicorn, `pilot`/`tool` для разовых процессов. Источник для `/manga/{id}` берётся из уже виденных ответов поиска, каталога и карточки, иначе `-`. |
| Сводка до/после | `python scripts/suwayomi-baseline.py --ssh mediavault-vm [--hours 24]` — только чтение: поиск владельца из `work`/`work_diagnostics` по маршруту (`_nativeAdapter`), задания индексации `catalogue_jobs` по маршруту, счётчик вызовов. |
| Сравнение двух путей | `python scripts/compare-source-paths.py --ssh mediavault-vm --source <ID> --query "<точное название>" [--chapter N] [--cbz] [--repeat 2]` — точный поиск, карточка, оглавление, открытие главы, первая картинка и, с `--cbz`, все страницы главы на обоих путях. Время каждого шага отдельно. Ничего не пишет в каталог, индекс и здоровье источников. Не запускается при `/opt/mediavault/deploy.lock`. |
| Пакетная проверка | `scripts/probe-native-source-batch.py` (с `--suwayomi` — тот же прогон через расширение). |

«Первая карточка» — время точного поиска до карточки в выдаче. «Первая страница» — открытие главы (список страниц) плюс первая картинка. У прямого пути карточка уже содержит оглавление, у Suwayomi это два запроса (`/manga/{id}` и `/chapters`).

## Переключение партиями

Партия — набор профилей, который агент C добавляет в [список активации](../server/manga_native_activation.json). Одна партия — один коммит, который меняет только этот список, с перечнем ID в описании. Так партию можно откатить одним `git revert`.

1. До выкладки партии: `probe-native-source-batch.py --source …` по ID партии на прямом пути и с `--suwayomi`, затем `compare-source-paths.py` по одному контрольному профилю каждого семейства и маршрута. Сравниваются точный поиск, карточка, число глав, открытие главы, первая картинка и CBZ.
2. Выкладка из main под lock. После неё поиск сбрасывает историю отказов и кэш запросов только у ID, чей маршрут изменился (`network_state.routes.native_ids`). Каталог остаётся доступен для начальной выдачи.
3. В течение суток: `suwayomi-baseline.py --hours 24`. Для ID партии вызовов `api` к Suwayomi быть не должно. Ненулевые вызовы по ID партии означают запасной путь после отказа прямого адаптера (`search_source`, задания `bridge` первой страницы) и разбираются по исходу.
4. Откат партии: `git revert <коммит партии>`, выкладка тем же способом. Поиск снова сбрасывает отказы этих ID, задания каталога с курсором `route: suwayomi` продолжают работу через Suwayomi.

Задания индексации продолжают работу с текущего курсора: у прямого адаптера и расширения курсор `{"page": N}` общий. Если у источника пагинация различается (другой размер страницы, курсор вместо номера, другой порядок), для него запускается отдельный проход с первой страницы. Записи объединяются по стабильному ключу `catalog_titles(provider, source_url)`, поэтому повтор не создаёт дублей. Задания с явным `route: suwayomi` дорабатывают свой курсор до конца; новые задания этих ID создаются уже на прямом маршруте.

Пустая выдача и таймаут не считаются прохождением. Источник, мёртвый на обоих путях, остаётся отдельным блокером с причиной.

## Проверка полноты

1. Снимок списка расширений на Oracle и сверка с исходным снимком 15.11 (`build-source-migration-register.py`). Исчезнувший ID — ошибка.
2. `--require-complete` по реестру: каждая операция каждого профиля `verified` или обоснованно `not_applicable`.
3. Старые ссылки: для каждого профиля открыть сохранённую ссылку `/__manga/suwayomi/m/…` без Suwayomi (агент D).
4. Источники с блокерами перечисляются отдельно с причиной и непройденными проверками.

## Остановка и откат

Каждый шаг выполняется только после явного подтверждения владельца в чате.

1. **Отключить запасные вызовы.** Выключить переход на Suwayomi в поиске, каталоге, читалке и при старте (`keep_domain_overrides` обращается к Suwayomi при каждом запуске импортёра). Проверить: старые ссылки, очередь индексации, чтение и скачивание главы с телефона. Откат: вернуть флаг.
2. **Остановить контейнер** `oracle-suwayomi-1` с сохранением образа, данных и APK. Держать остановленным не меньше одного полного цикла индексации, по счётчику — ноль вызовов. Откат: `docker start oracle-suwayomi-1`.
3. **Удалить сервис и APK** — только после шага 2 и отдельного согласия. Резервная копия данных Suwayomi и APK хранится срок, который выберет владелец.

После шага 2 японский маршрут и решатель должны работать без контейнеров Suwayomi: `suwayomi-jp-router` и `suwayomi-jp-vpn` сейчас обслуживают и прямые японские источники.
