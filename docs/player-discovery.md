# Точный тайтл, переводы и просмотр

Импорт передаёт выбранный ID каталога, aliases, тип и год, а не только поисковую
строку. `title_identity.py` отвергает противоречащие ID, год, тип и сезон.
Название должно совпадать точно после нормализации. Fuzzy-оценка не используется
для автоматического выбора. Если год известен у выбранной карточки, страница
источника должна подтвердить год или внешний ID. Неподтверждённые варианты не
попадают в список озвучек. Поэтому строгий поиск может вернуть меньше вариантов,
чем ручной поиск по одному слову, но не выдаёт случайное аниме за выбранное.

`player_catalog.py` обходит ограниченный граф публичных страниц и iframe.
Переводы группируются по нормализованному названию студии, типу и языку.
Субтитры не объединяются с озвучкой. Разные студии не склеиваются fuzzy-поиском;
неизвестные названия остаются отдельными вариантами с источником. Каждый вариант
сохраняет название страницы, сайт, плеер, реальные номера серий и сезонов.

Для AnimeGO используются `data-ptranslation`, `data-provider-title`,
`data-translation-title`, `data-player` и опубликованные пары episode ID/number.
Задание хранит ссылку на страницу конкретной серии с селектором перевода.
Перед скачиванием сервер заново читает её кнопки, получает свежий embed и
разрешает поток. При отсутствии нужной кнопки другая озвучка не подставляется.
Общий список серий страницы не является гарантией наличия каждой озвучки:
это явно перепроверяется у серии перед загрузкой.

CVH отдаёт playlist всех студий/типов и отдельный endpoint видео. Оба пути
разрешены точным списком; произвольные API URL по-прежнему запрещены. VK использует
парсер публичного embed из `anime-dl-core`; AniLiberty — собственный публичный
release endpoint. Kodik, Aniboom, Sibnet и Animedia остаются в реестре.
API-ключи из стороннего репозитория не копируются, Google credentials источникам
не передаются. В обработчик сохраняются тип/язык/плеер перевода, чтобы две версии
не потерялись при дедупликации и оставались доступны в собственном плеере.

Реестр сайтов расширен шаблонами поиска для DLE/HTML каталогов. Это конфигурации
адаптеров, а не доказательство, что каждый домен сейчас доступен. Зеркала меняются,
часть сайтов требует браузер, часть больше не отдаёт публичное видео. Каждый запрос
имеет deadline; источники обрабатываются с ограниченной параллельностью и кешем.
Ошибки, отсутствие точного совпадения и отсутствие доступного плеера различаются.
SovetRomantica не участвует в автоматическом поиске из-за описанной смены владельца
домена. Источники с Alloha/WebSocket, DRM, CAPTCHA и JS-only Jut.su не объявляются
успешно разобранными и не заменяются фальшивой ссылкой на видео.

## Обложки и библиотека

Заглушки `missing`/`404` отбрасываются. Современный постер Shikimori получается
через GraphQL по точному ID; связанные произведения обновляются тем же способом.
Профили версии 3 запускают обновление старых сохранённых описаний. Чтение
зашифрованных картинок ограничено четырьмя одновременными операциями. Повторная
догрузка обрабатывает ещё не сохранённые изображения вместо вечного повторения
первых 48. Старые эпизоды без кадров по-прежнему восстанавливаются задачей enrichment
на сервере; реальные кадры требуют доступа к Drive и декодируемого видео.

Русская и английская коллекции с одним точным MAL ID объединяются в интерфейсе,
включая варианты плеера, без перемещения старого ciphertext. Разные сезоны с разными
ID не объединяются. Связанные карточки дедуплицируются по ID, не по переводу названия.
Если каталог не предоставил русский перевод, его нельзя достоверно придумать.

## Просмотр

Прогресс разделён по Google subject, библиотеке и файлу. Сохраняется последний
эпизод коллекции; основная кнопка возвращает к нему, плеер показывает действие
«Продолжить просмотр» со временем. Завершённая запись очищается; блокировка
localStorage не ломает воспроизведение. Прогресс локальный для этого браузера,
не передаётся в Google cookies и не синхронизируется между устройствами.

WebGPU запрашивает `high-performance` adapter, и его device передаётся ONNX Runtime.
WebGL тоже запрашивается с high-performance. Anime4K получает прямую видеотекстуру,
когда не требуется предварительное уменьшение. В настройках отображается
фактический adapter/renderer, если браузер его раскрывает. Окончательный выбор
NVIDIA/AMD/Intel контролируется ОС и браузером: веб-страница не может его принудительно
назначить. Для дискретной карты в Windows можно назначить браузеру режим высокой
производительности в «Система → Дисплей → Графика» и перезапустить браузер.

«Порядок просмотра» использует точные ID графа франшизы и отмечает текущее
произведение. Отображается подтверждённый порядок выхода. Для Fate и других
альтернативных адаптаций не выдумывается единственная сюжетная хронология.
Календарь озвучек читает опубликованные `time`/date attributes и RSS источников;
японский эфир остаётся отдельным календарём и не считается датой готовности перевода.

## Проверка и развёртывание

Новые проверки: `tests/test_voice_discovery.py`, `tests/watch-progress.test.mjs`,
`npm run test:voices` (320/1280 px, выбор студии и плеера, точный ID, отсутствующие
серии, отсутствие браузерного видеотрафика). Существующие crypto/import/player
тесты также обязательны. Это офлайн-проверки; живые источники, конкретная GPU и
содержимое реального Drive требуют отдельной проверки из рабочей среды.

Backend объявляет версию 6. Обновить нужно и контейнер Oracle, и GitHub Pages.
Новый интерфейс сообщает о необходимости обновить backend версии 5, вместо
неверного вызова отсутствующего endpoint. Сохранённая база, OAuth credentials и
том `deploy/oracle/data` не удаляются и не пересоздаются. Новые облачные ресурсы
для этого изменения не требуются.
