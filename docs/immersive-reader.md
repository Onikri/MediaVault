# Читалка и просмотр из источника

## Интерфейс

Манга, манхва и книги используют общую полноэкранную оболочку. Панели
изначально скрыты и исключены из порядка Tab. Касание центра показывает меню,
касание края или свайп листает страницы с учётом направления. На компьютере
меню появляется у верхнего/нижнего края; стрелки листают, F включает полный
экран, Escape скрывает меню и затем закрывает читалку. При наведении на панель
или работе с клавиатуры она не исчезает.

Доступны отдельные панели глав, превью и настроек. На широком экране разворот
показывает две страницы, обложку отдельно; на телефоне остаётся одна страница.
Манхва открывается вертикальной лентой. Настройки манги и вебтунов разделены.
Позиция чтения сохраняется для профиля, библиотеки и файла. Данные новой главы
не перезаписываются позицией предыдущей во время загрузки.

EPUB использует локально собранный epub.js; PDF — PDF.js с отдельным worker;
TXT поддерживает UTF-8 и Windows-1251, FB2 извлекает текст без исполнения HTML.
Настройки перевода вынесены в отдельную вкладку: локальный LMT, ВМ и личный
Google API сохраняют очистку, LaMa, автовёрстку и кэш. Визуальные панели не
занимают место у страниц. Перевод продолжает работать при скрытом меню.

## Библиотека и импорт

Переключатель «Google Диск / Онлайн» сохраняется для пользователя. Онлайн
использует существующие защищённые `/online/prepare` и потоковые capability
URL, без постановки задания в очередь Drive. Вход владельца на сервер остаётся
обязательным; открывать/расшифровывать Drive для онлайн-просмотра не требуется.
Манга запрашивает изображения по мере чтения, видео — части HLS или Range.
Это не режим без сети: данные должны поступать из источника. PDF/EPUB/TXT/FB2
по прямой ссылке пока считываются целым файлом, источник должен разрешать CORS.

Выбор серии/главы ограничивает онлайн-очередь. В конце главы можно перейти к
следующей без выхода из читалки. Выбранный предел качества передаётся серверу.
На новом backend HLS master не требует предварительной проверки всех качеств;
первый уже проверенный manifest переиспользуется в памяти на протяжении 30 с.
При ограничении качества сохраняются подходящие варианты и внешние аудиодорожки.
Таймер и повтор подключения доступны при ошибке источника.

Музыкальная панель поддерживает очередь, громкость, поиск по времени, избранное
и MediaSession для собственных аудиофайлов/потоков/Drive. Записи YouTube по умолчанию играют через аудиопоток Oracle. Официальный
YouTube-плеер открывается по явному выбору. Панель
собственного аудио скрывается вместе с меню читалки. Выход из профиля/блокировка
закрывают воспроизведение и освобождают Blob URL.

## Дополнительный источник WEBTOON

Добавлен английский WEBTOON Originals и Canvas (один адаптер, два каталога).
Поиск сверяет полное название и известные синонимы; похожие истории из Canvas
не становятся совпадением автоматически. API списка опубликованных выпусков
разрешён только на конкретном публичном host/path. Номера сезонов, нулевая и
дробные главы сохраняются. В читалке используются только `#_imageList > img`;
реклама, обложка и недоступные платные страницы не подставляются вместо страниц.

Протокол сверён с [Keiyoushi Webtoons.kt (Apache-2.0)](https://github.com/keiyoushi/extensions-source/blob/main/src/all/webtoons/src/eu/kanade/tachiyomi/extension/all/webtoons/Webtoons.kt),
Git blob `9d422e737f17ac4fbf4c50c9aa8c79e48f96298a`.
Фактический сетевой тест из рабочего окружения, не из Oracle:
[результат Originals и Canvas](benchmarks/webtoons-live-2026-10-28.json).
Проверены список глав, список изображений главы и реальные байты первой страницы.

## Проверки и пределы

`npm run test:reader` проверяет CBZ, разворот, ленту, превью, TXT, PDF с настоящим
worker, EPUB с настоящим движком, восстановление позиции, онлайн без Drive-job,
импорт выбранной корейской главы и воспроизведение WAV на 390/1366 px.
`test:online` проверяет реальное HLS-воспроизведение тестового видео, переход
глав, закрытие сеанса и официальный YouTube-контракт. `test:direct`, `test:vm`
и `test:translation` проверяют сохранение путей перевода, очистку и кэш.
Ответы Google в этих browser-тестах — явные fixtures, а не замеры моделей.
Python-проверки импорта используют FakeDrive и проверяют реальную сборку CBZ,
шифрование/расшифрование, возобновление и дедупликацию. В Drive пользователя
тестовые файлы не записывались.

Фронтенд совместим с уже установленным backend v12. Дополнительный WEBTOON
и сокращение запросов HLS требуют установки новой серверной ревизии через
`deploy/oracle/update-from-cloud-shell.py`. Публикация Pages сама по себе не
обновляет Oracle.
