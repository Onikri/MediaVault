# Читалка, перевод и музыка · 5.4

## Чтение и трафик

Манга, манхва, маньхуа и вебтуны остаются одним типом каталога с разными форматами. Для манхвы и вебтунов первая настройка — непрерывная лента. Доступны постраничный режим, оба направления, ширина 640–1600 px, тёмная/бумажная/OLED тема, предзагрузка 0/1/2/4 страниц и подготовка следующей главы. Настройки и позиция чтения привязаны к профилю на устройстве.

Новые серверные CBZ используют ZIP_STORED. Читалка читает центральный каталог ZIP и нужное изображение через `readRange`: из Drive скачиваются и расшифровываются только затронутые части по 4 МиБ. В памяти не больше четырёх расшифрованных частей и пяти страниц. При выходе из аккаунта кэш очищается. Расшифрованные главы не сохраняются в cookies, IndexedDB или Service Worker. У старых сжатых CBZ — совместимая загрузка архива целиком. Следующая глава подготавливается по частям; целые тома без запроса не скачиваются. При `navigator.connection.saveData` фоновая предзагрузка выключена.

Экономное/сбалансированное качество выбирается **при импорте**. Oracle уменьшает изображения до 1280/1920 px по ширине и сохраняет JPEG, затем собирает CBZ и шифрует его. Оригинал сохраняется без изменений при выборе «Оригинал». Сжатие браузером после скачивания не выдаётся за экономию сети.

## Источники

MangaPoisk и MangaHub — русские переводы. В импорте есть независимый выбор «Все языки / Русский / English». В режиме «Все» MangaPill ищется даже при наличии русских источников; старые клиенты сохраняют резервный EN-поиск. Для независимого поиска требуется сервер API 10; на прежнем сервере доступен импорт английской версии по прямой ссылке. Для MangaPill используются опубликованные ссылки и `img.js-page`; API-ключей, оплаты, cookies источника или обхода платных глав нет. Выбранный тайтл повторно сверяется при проверке источника. Английская глава сохраняет `translationInfo.language=en`; оригинальные страницы остаются зашифрованными в Drive.

Возрастные отметки и форматы берутся из метаданных. Отдельная специализация на порнографических материалах не добавлена.

## Бесплатный EN → RU

Проверены открытые проекты:

| Проект | Лицензия | Решение |
| --- | --- | --- |
| [manga-image-translator](https://github.com/zyddnys/manga-image-translator) | GPL-3.0 | Полноценный перевод изображений, но тяжёлые модели/зависимости для 2 ARM CPU; код не копировался |
| [mokuro](https://github.com/kha-white/mokuro) | GPL-3.0 | Сильный японский OCR и HTML-просмотр, не готовый EN → RU; код не копировался |
| [Suwayomi-WebUI](https://github.com/Suwayomi/Suwayomi-WebUI) | MPL-2.0 | Изучены возможности читалки; интерфейс MediaVault написан отдельно |
| [Argos Translate](https://github.com/argosopentech/argos-translate) | MIT/CC0 | Пакет EN → RU, локальный CTranslate2 INT8 + SentencePiece, без Stanza/Torch |
| [Tesseract](https://github.com/tesseract-ocr/tesseract) | Apache-2.0 | Английский OCR, один поток, TSV с координатами |

В Docker установлены Tesseract, Pillow, CTranslate2 и SentencePiece. Установка модели один раз:

```sh
docker exec <существующий-контейнер> python reader_translation.py
```

Скачивается пакет Argos `translate-en_ru-1_9.argosmodel` (~187 МиБ); SHA-256 закреплён в коде. Извлекаются только модель, токенизатор и сведения об источниках. Каталог `/data/reader-models` переживает перезапуск контейнера. GPU и платные сервисы не нужны.

`GET /reader/translation` показывает готовность, `POST /reader/translate` доступен только существующему владельцу через серверную сессию. Видимая страница передаётся по HTTPS на **его** Oracle. Не записывается в каталог/логи; временный файл OCR удаляется. Текст и координаты возвращаются браузеру. Результаты OCR/перевода кэшируются в памяти сервера до 6 часов, не более 128 страниц, с разделением по аккаунтам; исходные изображения в кэш не попадают. На странице — отключаемый русский слой, оригинал остаётся доступен. При английском импорте перевод включается по умолчанию, если пользователь ранее не сохранил другую настройку.

Лимиты: одно задание перевода одновременно, один CPU-поток модели, 10 МиБ/24 Мп на изображение, Два прохода OCR до 20 секунд каждый, максимум 60 текстовых блоков. Первый находит строки, близкие строки объединяются в реплики; второй перечитывает каждую реплику целиком, чтобы не терять короткие слова и отрицания. Это машинный перевод: он хуже профессиональной локализации, может ошибаться на рисованном шрифте и сложных панелях. Сейчас исходный язык **английский**. [Публичный пример двух реплик](https://onikri.github.io/MediaVault/translation-demo.html) показывает заранее рассчитанный результат на реальном фрагменте; это не имитация живой авторизации или импорта в Drive. Японский/корейский OCR, удаление текста с восстановлением рисунка и перевод всей библиотеки в фоне не реализованы.

## Музыка и официальные площадки

`GET /music/anime/{malId}` запрашивает бесплатный AnimeThemes, проверяет ресурс MyAnimeList с тем же ID и возвращает OP/ED, исполнителей и серии. Аудио и клипы AnimeThemes не скачиваются. Кэш 6 часов, отсутствие данных — 90 секунд. В плеере и на странице аниме есть список тем; любимые песни доступны в разделе «Музыка», отдельно для аккаунта на устройстве.

- Поиск песни в Spotify и YouTube Music работает без приложения/ключей.
- Spotify: OAuth Authorization Code + PKCE S256, публичный Client ID, зарегистрированный `https://onikri.github.io/MediaVault/spotify-callback.html`. Client Secret не нужен. Записи ищутся через Spotify API; пользователь выбирает конкретную запись и плейлист перед добавлением. Правила/доступность Spotify Developer API зависят от приложения и аккаунта; бесплатность или доступ для любого пользователя не обещаются.
- YouTube / YouTube Music: дополнительное разрешение Google `youtube`, YouTube Data API в бесплатной квоте существующего проекта. Загружаются собственные плейлисты, результаты поиска; запись добавляется только после выбора пользователем. Google Drive scope не меняется. У YouTube Music нет отдельного общедоступного API для таких операций, используются совместные плейлисты YouTube.
- Токены обеих площадок хранятся в памяти вкладки, удаляются при выходе из MediaVault. Нет фоновых загрузок музыки и извлечения аудио.

Реальные чужие аккаунты не авторизовывались и их плейлисты не изменялись во время тестов. PKCE/запись проверяются отдельным браузерным тестом контрактов. Полноценное прослушивание осуществляется на официальной площадке, с её региональными/аккаунтными ограничениями.

Точные музыкальные таймкоды в фильмах и сериалах **не выдумываются**. AnimeThemes даёт серии, но не позицию песни в видео; автоматический универсальный аудиофингерпринтинг без базы записей здесь не реализован.

## Трейлеры в своём плеере

Существующая цепочка каталожный трейлер → yt-dlp → временный файл Oracle → VideoPlayer сохранена. Добавлен выбор отдельных MP4 video + M4A audio со сборкой ffmpeg, когда YouTube не предоставляет единого файла. До 720p/10 минут/100 МиБ, временный ограниченный кэш. Только разрешённые видеохостинги и ID из каталога. Без cookies входа, DRM или обхода проверки YouTube; недоступный ролик получает явный статус ошибки. Бесплатная VM не гарантирует доступ YouTube с каждого IP.

## Надёжность запоминания устройства

Ключ для запоминания создаётся через атомарный `getOrPut` в IndexedDB: параллельные вкладки используют один выбранный неэкспортируемый ключ. Записи выполняются с `durability: strict`. При включённом запоминании библиотека становится открытой в интерфейсе после завершения сохранения защищённого ключа, чтобы немедленная перезагрузка не прервала эту операцию. Секретная фраза в cookies или localStorage не записывается. Проверка восьми одновременных сохранений переживает перезагрузку; полный сценарий включает WebAuthn и выход.
