# Первая переведённая страница раньше фоновой главы

В читалке и при сохранении главы приоритет имеет первая видимая страница.
Для обычной манги она идёт отдельным запросом и не ждёт загрузки, разметки
или ответа для соседних страниц. После готовности её изображения продолжаются
фоновые пакеты. При возобновлении чтения загрузчик начинает с видимой страницы.
Соединённая реплика на шве вебтуна сохраняет необходимый соседний контекст.

Тот же порядок используется локальным сохранением из читалки и экспортом на
ВМ: первая несохранённая страница обрабатывается до фонового окна. Готовые
страницы по-прежнему пропускаются, полный CBZ/PDF собирается после завершения
страниц. Параллельная загрузка оригиналов без перевода сохранена.

Проверка языка больше не ждёт медленную соседнюю страницу дольше 350 мс,
если текущая уже подготовлена. Быстро доступные две страницы используются
по-прежнему; результат содержит фактически проверенные номера. Для обращения
через Oracle убрана дополнительная клиентская пауза. Неуверенное определение
не заменяет выбранный язык догадкой.

## Серверный приоритет и страхующий запрос

Google gateway v5 принимает приоритет interactive/background. Для первого
запроса серверного пула после четырёх секунд ожидания может стартовать второй
worker с тем же запросом и моделью через **другой известный проект**. При
быстром ответе второго запроса нет; один проект/неизвестные общие проекты
не размножают квоту и не запускают такую гонку. Личный ключ не подключает
серверные ключи без явного режима пула.

Максимум два запроса Google одновременно на этот первый запрос. Каждый проект
в его обработке пробуется один раз, 429/5xx учитываются обычным ограничителем.
Первый полученный ответ возвращается, незавершённый worker отменяется и
освобождает слот. Отмена на нашей стороне **не отменяет расход квоты или
возможную оплату у Google**: обе попытки остаются в журнале. При активном
интерактивном запросе фоновая очередь оставляет два из общих шести слотов.
Закрытие клиентом и общий deadline закрывают workers; продолжительное ожидание
ответа возвращает 504, а ограничение квоты — 429.

Модель, разрешение и качество очистки ради скорости не понижены. Старый gateway
сохраняет совместимый путь; priority передаётся только после подтверждения v5.

## Реальный контрольный прогон на Oracle

Использован тот же синтетический набор из шести страниц с английскими репликами,
что и в [предыдущем замере](google-translation-throughput-2026-11-12.md):
900×1300, одинаковый шаблон диалога, Gemini 3.5 Flash Lite, блоки, en-fast,
очистка fast, настоящий Google API и Canvas. Язык для экспорта был задан;
отдельная проверка языка в это время не включена.

| Метрика | Предыдущая версия | С приоритетом первой страницы |
| --- | ---: | ---: |
| Готовность страницы № 1 | 47,799 с | **7,637 с** |
| Все 6 страниц | 61,205 с | **15,931 с** |
| Первое обращение фоновой страницы к gateway | 3,790 с* | 7,931 с |
| Готовые изображения с проверенной PNG | 6 | 6 |

\* В предыдущем прогоне все страницы отправлялись одной фоновой волной;
запросы начинались от 3,790 до 4,839 с, без отдельного приоритета страницы № 1.
В новом прогоне первый запрос имел interactive, остальные пять — background
и начались после сохранения первого изображения в 7,637 с.

Это один прогон на синтетических страницах, не гарантия задержки для любой
манги: изменчивость Google и реальное содержимое также влияют на время.
Японский OCR, нейросетевой инпейнтинг и качество перевода на большой выборке
этим тестом не измерялись. [Исходные замеры](benchmarks/translation-first-page-2026-11-12.json).

Отдельные контрактные Node/Python тесты используют явные фикстуры Google,
детектора и изображения. Они проверяют заблокированного соседа, выдачу первого
изображения до фоновой отправки, скачивание, отмену проигравшего запроса,
отсутствие утечек слотов, общие квоты проекта и совместимость старого API.
Production сборка и реальный экспорт выполнены отдельно от этих фикстур.

На ВМ установлен образ ревизии `c2f551be85434f86236146ae7f62ec0d29087705` с
gateway v5. Его зависимости сверены с ранее работавшим образом; обновлены
код и собранные export assets. Установщик проверил хэши исходников, создал
полную приватную резервную копию и сохранил настройки, OAuth, ключ и задания.
