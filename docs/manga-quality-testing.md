# Сравнение моделей и шрифты

Продолжение прежней работы: ветка `codex/manga-backend-processing`, последний
проверенный исходный commit `cc005d4537d040b8df38a63617af949529c447bf`.
Существующий Oracle-стенд — `/opt/mediavault-reader-bench`; production importer
и его data volume не заменяются. Старый успешный WASM-проход CTD → Manga-OCR →
Qwen3 4B → LaMa уже измерен: 173,160/130,647 с. Его не нужно повторять.
Подробности: [старый отчёт](https://github.com/Onikri/MediaVault/blob/codex/manga-backend-processing/docs/oracle-lmt-benchmarks.md).

## Шрифты

В настройках перевода доступны Comic Relief (по умолчанию), Pangolin, Neucha и
системный вариант. Тот же шрифт применяется к серверным текстовым слоям и к
набору LMT. Веса шрифта загружаются до расчёта метрик строки. Файлы локальные;
шрифт и положение чтения сохраняются в существующих настройках пользователя.
Шрифты OFL, их источники и SHA-256 — `reader-fonts/manifest.json`.

## Отдельный стенд компонентов

`scripts/benchmarks/` не загружается обычной читалкой и не запускается CI с
моделями. Он сохраняет результат после каждого случая. `--resume` проверяет
отпечаток модели/сборки/разметки; изменившиеся входы не смешиваются с отчётом.
Модели, изображения и профили браузера остаются вне Git.

- `manga_cases.py`: собственные страницы с соседними пузырями, низким контрастом,
  наклоном, текстом поверх рисунка, длинным вебтуном и печатными JP/KR репликами.
- `run-browser.py`: настоящие RT-DETR/CTD и OCR из LMT, WASM CPU либо нативный
  ONNX CPU через тот же мост, что в предыдущей ветке. Сравнение детекции —
  однозначное сопоставление текстовых рамок при IoU≥0,3; это не метрика маски
  пузыря. OCR сравнивается на истинных рамках, отдельно от ошибок детектора.
- `run-text.py`: Argos, OPUS-MT, NLLB-200 и свой OpenAI-compatible LLM, с одинаковыми
  исходными репликами и полными сохранёнными ответами. chrF++ служит дополнением
  к ручной проверке смысла; синонимы могут снижать балл без ошибки перевода.
- `run-inpaint.py`: заливка, Telea, Navier–Stokes, LaMa Manga, MI-GAN; одинаковые
  маски и известный чистый фон. Сохраняются картинки, ошибка внутри маски и
  изменение рисунка снаружи. Это синтетический стресс-тест, не общий рейтинг.
- `run-llm.py`: llama.cpp слушает только 127.0.0.1 и останавливается в finally.

Сначала нужны реальные веса и их SHA-256; фиктивные ответы не считаются
инференсом. Локальные x86_64 результаты и Oracle aarch64 публикуются отдельно.
Ограничение GPU браузера не позволяет честно назвать WebGPU-имитацию тестом
дискретной видеокарты.

Пример локального запуска:

```sh
python scripts/benchmarks/manga_cases.py
node scripts/benchmarks/build-browser.mjs
python scripts/benchmarks/run-browser.py --runtime native --label LOCAL-x86_64 --stages detection,ocr,fonts
python scripts/benchmarks/run-inpaint.py --label LOCAL-x86_64
```

Для Oracle используется дополнительный Dockerfile поверх уже подготовленного
образа `mediavault-reader-bench:cc005d4537d0`. Веса и результаты монтируются из
отдельной benchmark-папки. Новые OCI ресурсы, платные API и публичные LLM порты
не нужны. Полная интеграция backend/editor из прежней ветки не объявляется
развёрнутой только из-за успеха этих измерений.

Итоговые реальные измерения и выбранный JP-профиль качества:
[сравнение моделей на Oracle A1](manga-model-comparison-2026-10-26.md).
