# Быстрый перевод с личным ключом

Читалка → Настройки → Где обрабатывать → **Быстрый · личный ключ Google**.
Ввести личный ключ AI Studio и нажать «Применить личный ключ».
По умолчанию: английская манга, направление справа налево, лёгкий контурный поиск английских букв
без моделей, Gemma 4 26B A4B, строго одна страница, лёгкая очистка, автоматический
выбор кириллического шрифта. Доступны 31B, Flash Lite 3.5 / 3.1 / 2.5 и RT-DETR INT8 для сложных страниц.

Это третий самостоятельный режим. Исходные страницы загружаются обычной
читалкой; после расшифровки устройство в Canvas Worker находит компоненты букв, соединяет строки в текстовые блоки и определяет координаты. Контурный режим экспериментальный: на сложном рисунке, светлом/мелком тексте может пропускать реплики; для таких страниц можно явно выбрать RT-DETR. На
уменьшенной WebP-копии рисуются уникальные метки `P1_B1` и далее. Одна отдельная картинка отправляются непосредственно в Google REST API.
Ответ содержит только ID, русский перевод, тип текста и стиль шрифта.
Координаты сохраняются локально и никогда не принимаются из ответа модели.
Предыдущие реплики передаются как ограниченный контекст. Рисунок очищается
и русский текст вставляется в существующем Canvas Worker.

Убраны очередь ВМ, countTokens, отдельный OCR, LaMa, развёрнутая JSON-схема,
обратная пересылка исходной транскрипции и автоматические повторы. Google
получает `thinkingLevel: MINIMAL`. На запрос даётся 30 секунд; при лимите или
сбое показывается ошибка с ручным повтором. Один Google-запрос выполняется
одновременно, видимая страница имеет приоритет перед предзагрузкой. Предзагрузка по умолчанию выключена; при включении каждая следующая страница переводится отдельным запросом. Медленное
чтение соседнего файла не задерживает отправку уже подготовленной страницы.

Ключ хранится в памяти вкладки; по отдельной отметке — в sessionStorage до
закрытия вкладки. Не передаётся на Oracle, в URL, localStorage настроек или
идентификаторы кэша. Блокировка хранилища удаляет ключ. Каждая страница JSON
кэшируется зашифрованно в IndexedDB с привязкой к профилю, библиотеке,
исходным байтам, главе, индексу страницы, модели и направлению. Кэш читается
до проверки ключа; готовую страницу можно повторно открыть без запроса.

На экране показываются фактические этапы и время. После готовности отдельно
видны время Google и детекции. Цель в 10 секунд не является гарантией:
скорость Google и первый запуск WASM/скачивание модели влияют на задержку.
Контурный режим не загружает веса или ONNX Runtime. Опциональный RT-DETR весит 11 120 765 байт; для него отдельно загружается ONNX Runtime WASM.

Проверки: `node --test tests/manga-direct.test.mjs`, `npm run test:direct`.
Браузерная проверка запускает настоящий контурный детектор и Canvas Worker с
кириллическими шрифтами. Ответы Google в ней — явные тестовые ответы: она
проверяет контракт, максимум две картинки, ключ, очистку, кэш и интерфейс,
но не измеряет скорость или качество настоящего API. Для запуска того же сценария с RT-DETR: `DIRECT_DETECTOR=rtdetr npm run test:direct`. Результаты реального
детектора/рендера сохраняются в `test-output/manga-direct-browser-metrics.json`.

Фактический smoke-тест CaaS x86_64: контурная детекция 509/272 мс, очистка 78/45 мс, полный рендер Worker 340/191 мс (390/1366 px). Веса не скачивались; Google был тестовым ответом. Холодный RT-DETR WASM на той же тестовой среде потребовал 42,7/51,6 с: поэтому он не выбран по умолчанию. Это ограниченный тест собственных английских страниц, а не оценка полноты на всей манге и не обещание десятисекундного ответа Google.

## Диагностика Google · 27 октября 2026

Быстрый режим принудительно использует один скан за вызов даже для старых
сохранённых настроек с двумя страницами. Дополнительные варианты выбираются
вручную: `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite` с
`thinkingLevel: MINIMAL`, `gemini-2.5-flash-lite` с `thinkingBudget: 0`.
Для Gemini 3.x не передаётся устаревающая настройка temperature. ВМ и её
ключ/модели не меняются. Клиентские тайм-ауты: 30, 60 или 120 секунд.

Панель «Запрос Google и подробные метрики» показывает реальный JSON без
встроенной base64-простыни, размеченный скан, локальные координаты, байты
UTF-8 тела запроса, размер каждого сжатого изображения и параметры генерации.
Полный JSON с изображением скачивается отдельной кнопкой; API-ключ хранится
только в заголовке и в файл/копируемый отчёт не попадает. Размер тела до
отправки проверяется по лимиту 20 000 000 байт. Это не проверка TPM/RPM:
проектные квоты доступны из ответа Google при 429, а точные использованные
токены, включая thinking, — из usageMetadata после ответа.

XMLHttpRequest даёт отдельные события upload, заголовков, первого блока
ответа и завершения. Время до upload.onload включает соединение и CORS;
время до ответа включает сеть и сервер, а не чистый inference модели.
Неизмеренные значения не заменяются нулями. В таблице также отображаются
измеренные этапы детекции/маркировки/сжатия, JSON/валидации и рендера.
Отсчёт начинается после получения исходника читалкой. Тайм-аут и сетевой
отказ сохраняют уже полученные метрики. HTTP-код, API status, quota/retry
и INVALID_ARGUMENT сохраняются с удалением значения личного ключа.
Диагностика живёт в памяти, не раздувает кэш переведённых глав.
«Повторить без кэша» обходит память и IndexedDB только для выбранной страницы.

Источники проверки контрактов:
- https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite
- https://ai.google.dev/gemini-api/docs/generate-content/thinking
- https://ai.google.dev/gemini-api/docs/image-understanding

Тесты Google в браузере по-прежнему используют явные ответы fixtures: это
проверка UI, XHR-контракта, ошибок и кэша, а не измерение реальной задержки
Google или диагностика личного запроса пользователя.

## Инпейнт и нативная Gemma

Вернулся выбор «Авто / LaMa / Быстро». Старый принудительно быстрый профиль
переходит на «Авто». Описание трёх этапов, кэшей, гарантий сохранности рисунка
и реальных ограничений: [Процессор текста](reader-text-processor.md).
У Gemma по умолчанию отдельный потоковый нативный профиль с компактным
ответом, без JSON grammar. Flash сохраняет прежний запрос. Для нового
сетевого сравнения нужно нажать «Повторить без кэша»; повтор инпейнта и
смена локальных настроек используют сохранённый перевод.

## Поиск текста и координаты Google (27.10.2026)

В настройках появились три входа: рамки/ID, чистая страница с локальными
координатами и самостоятельный поиск Google без детектора. В быстром режиме
также доступны CTD, YOLO26n Manga и PP-OCRv6 Manga. Кнопка сравнения запускает
три отдельных запроса и показывает рамки и метрики. Формат, ограничения и
фактические тесты описаны в [google-text-detection.md](google-text-detection.md).
