# MediaVault

Мобильная медиатека на React/Vite: манга, видео, книги, музыка и изображения в собственном Google Drive. Новый интерфейс использует Radix UI, Motion и Lucide. В библиотеке показываются реальные файлы из расшифрованного каталога.

**Сайт:** https://onikri.github.io/MediaVault/

**Автоматический сервер импорта:** [Oracle Always Free — конфигурация и развёртывание](deploy/oracle/README.md). Сервер владельца настроен на `https://141.144.225.42.sslip.io`; фоновый доступ к Drive владелец завершает один раз в настройках импорта. Проверка состояния: `/health`.

## Первый запуск

1. Открой **Профиль → Войти через Google** и разреши чтение файлов Drive в окне Google. Отдельная кнопка подключения и ввод ID не требуются: приложение само ищет библиотеку после входа. Владелец — аккаунт `roma.shevchenko2020@gmail.com`. В коде хранится SHA-256 адреса для определения администратора. Папка другого аккаунта не используется: `storageFolderId` пустой, новая библиотека создаётся в Drive вошедшего владельца.
2. Если библиотека найдена, введи только её секретную фразу. Если библиотек пока нет, придумай и повтори фразу длиной от 12 символов → **Создать мою библиотеку**. Папка, зашифрованный каталог и ID создаются автоматически. Фразу нужно придумать самому: это не пароль Google, получить её в Google Cloud нельзя. Сохрани её, восстановления нет.
3. В **Библиотеке** можно добавлять локальные файлы или папку целиком. Формат определяется автоматически. Разделы «Аниме», «Манга», «Ранобэ», «Книги», «Музыка» отделены друг от друга. Укажи название тайтла/альбома и при необходимости сезон/том. При выборе папки дерево вроде `Ранобэ/Название/Том 1/...` разбирается автоматически. EPUB/PDF сам по себе не отличает ранобэ от обычной книги — раздел можно выбрать вручную.
4. Если найдено несколько библиотек, выбери нужную из списка. Проверка Drive не создаёт файлов; при ошибке доступа новая пустая библиотека не предлагается. Перед созданием приложение повторно проверяет наличие каталога, чтобы избежать случайных дубликатов. Для редкого ручного открытия достаточно вставить полную ссылку в «У меня есть ссылка на другую библиотеку».

Кнопка **Пригласить** выдаёт другу право чтения папки в Drive. Передай ссылку и секретную фразу отдельно. Для зрителя приложение запрашивает только чтение Drive.

Вход сразу запрашивает чтение Drive. При создании или первом изменении библиотеки Google может дополнительно попросить разрешить запись; это происходит из соответствующего действия автоматически. Зрителям доступ на запись не запрашивается.

Публичный Google OAuth Web Client ID уже указан в `config.js`. Веб-сайт не хранит пароль Google, Client Secret или ключи сервисного аккаунта. Для фоновой работы серверу нужен Client Secret только в его приватной конфигурации; в GitHub он не публикуется. Если Google отклоняет вход, в проекте OAuth должны быть включены Drive API, origin `https://onikri.github.io` и тестовые пользователи, включая владельца. Для локального запуска origin — `http://localhost:8080`. В origin нельзя добавлять путь проекта.

## Разделы и тайтлы

Одна библиотека — общий корень хранилища и одна секретная фраза. Это не общая папка со всеми сериями вперемешку. В режиме «Тайтлы» каждый тайтл показан отдельной карточкой; внутри находятся сезоны, тома и файлы. В режиме «Файлы» доступен общий список. Поиск работает по названию тайтла и файла.

```text
MediaVault
├── Аниме → Наруто → Сезон 1 / Сезон 2 → серии
├── Манга → Наруто → Том 1 / Том 2 → главы
├── Ранобэ → Название → тома
├── Книги → Название книги → файлы
└── Музыка → Альбом → треки
```

Одноимённые аниме, манга и ранобэ имеют разные папки. Сезоны одного аниме используют общую папку тайтла. Старые каталоги и ссылки на зашифрованные блоки читаются без перемещения или повторного шифрования существующих файлов; новые загрузки используют расширенную структуру `storage.version = 2`.

## Мировой каталог и автоматический импорт

Вкладка «Импорт» объединяет бесплатные каталоги **Kitsu, AniList, Shikimori,
MyAnimeList через Jikan, IMDb, TVmaze и Wikidata**. Ключи платных сервисов не
используются. Kitsu/AniList покрывают аниме и мангу; IMDb/Wikidata — кино,
TVmaze — сериалы. Ни один источник не содержит буквально все произведения мира.
Клиент объединяет записи по внешним ID и названиям, сохраняет синонимы на разных
языках и не подменяет недоступный источник демонстрационными карточками.

Поиск начинает запрос через 350 мс после ввода, отменяет устаревшие ответы,
показывает результаты каждого каталога по мере готовности и подсказки с
клавиатурной навигацией. Точные совпадения названий и синонимов стоят первыми.
При быстром вводе старые карточки сразу убираются; промежуточные символы IME
не отправляются до окончания набора. Сбой одного источника не блокирует
остальные, ошибочный ответ не кешируется, доступна кнопка повторного поиска.
Если серверный IP не может получить бесплатные метаданные, клиент пробует
прямой запрос к тому же открытому каталогу с поддержкой CORS. Это касается
только метаданных; HTML источников и видео обрабатывает сервер. IMDb остаётся
на сервере, поскольку его подсказки не поддерживают прямой CORS-доступ.
Русский, английский, японский, китайский и корейский
передаются каталогам без потери символов; наличие перевода зависит от их баз.
Если Kitsu, AniList или Jikan не находят кириллическое название, клиент один раз
проверяет латинское написание (например, «Наруто» → `naruto`) и отмечает это
рядом с результатами. Транслитерация не переводит названия: «Атака титанов»
по-прежнему требует русского синонима в каталоге или оригинального названия.
Фильтры года передаются поддерживающим их сервисам; жанр/формат/возраст
применяются к полученным карточкам страницы. Фильтр озвучки сверяет первые
24 карточки страницы по публичному HTML источников на сервере, с кешем
15 минут и двумя одновременными проверками. Это проверка доступности, а не
полный индекс всех переводов; ошибки не считаются доказательством их отсутствия.

Карточка содержит реальные обложку, описание, жанры, теги, ограничения, даты и
число серий/глав, если источник их вернул. Неизвестные значения не выдумываются.
Японский эфир отображается в JST, публикации озвучки — отдельно и только когда
сам источник указал дату для эпизода/релиза. Выход в Японии не считается выходом
русской озвучки. Услуги метаданных могут ограничивать запросы или быть недоступны.

Схема импорта: **публичный источник → свой сервер → зашифрованный Drive**.
Видео не проходит через телефон, GitHub Pages или Cloudflare Worker. Drive не
скачивает произвольный URL сам — парсер и ffmpeg работают на VM. Интерактивного
запуска блокнотов в этом сценарии нет.

1. Сервер Oracle и публичный `importServerUrl` уже настроены. Для нового
   развёртывания используй [инструкцию Oracle](deploy/oracle/README.md).
   В «Импорт → Сервер импорта» добавь показанный redirect URI в существующий
   Web OAuth-клиент Google. В его правой панели выбери Client secrets → Add Secret
   и вставь новый секрет в защищённое поле Client Secret на сайте. Google показывает
   секрет только при создании; ранее сохранённый JSON тоже можно использовать.
   Сервер получает только Client ID и Client Secret;
   секрет хранится зашифрованным и не возвращается браузеру.
2. Войди владельцем, открой библиотеку и один раз разреши серверу фоновый Drive.
3. Найди тайтл, открой карточку, выбери найденную страницу, озвучку и сезон.
   Можно добавить всю опубликованную часть, одну серию, диапазон или список.
4. Нажми **Импортировать в коллекцию**. Задание остаётся на сервере после
   закрытия вкладки. Прогресс виден в «Загрузках»; коллекция обновляется сама.
   Отдельный режим «По ссылке» принимает публичные плееры, MP4/HLS и главы.

Сервер обрабатывает один файл за раз, проверяет результат, шифрует блоки по
4 МиБ и загружает их в Drive. Названия, описание, обложка и сведения о тайтле
попадают в зашифрованный каталог коллекции; сайт использует их после открытия.
Временное видео удаляется после файла. Токены Google используются только
адаптером Drive и не отправляются источникам. Шифрование на сервере требует
передачи ему производного ключа открытой библиотеки по HTTPS, без передачи фразы.

Очередь и Google refresh token зашифрованы на приватном диске VM; успешные и
отменённые задания удаляют свой ключ из записи, остальные истекают через 7 дней.
Перезапуск повторно ставит прерванное задание в очередь. Манифесты завершённых
файлов хранятся в Drive: повторный импорт их пропускает. После потери самой VM
можно развернуть сервер снова и отправить то же задание без повторной загрузки
сохранённых серий. Остановка пользователем происходит между файлами.

Бесплатные квоты и доступность VM проверяются в аккаунте; PAYG автоматически не
включается. Бюджеты Oracle уведомляют о расходах, но не запрещают списания.
Одна очередь сериализует серверные записи; пока она работает, не изменяй тот же
каталог с другого устройства. Drive v3 не гарантирует атомарный compare-and-swap.

## Публичные источники и плееры

Собственный `server/source_parser.py` извлекает ссылки и опубликованные эпизоды из HTML, `iframe`, атрибутов плееров и текстовой конфигурации. Реестр использует [anime-dl-core 0.5.1](https://github.com/ialakey/anime-dl-core), MIT: **Kodik, Aniboom, CVH, Sibnet, Animedia, AniLibria/AniLiberty, VK и исторический SovetRomantica**. Открытые playback endpoints CVH и каталог/релизы AniLiberty разрешены точным списком; ключ разработчика не требуется. Произвольные API, авторизация и cookies владельца источникам не передаются. SovetRomantica исключён из автоматического поиска из-за смены владельца домена; его исторический формат проверяется сохранёнными ответами. Для Jut.su и Alloha предусмотрен отдельный изолированный Chromium. Список адаптеров не является результатом живой проверки каждого сайта.

Восемь форматов из статьи проверяются реальными сохранёнными ответами в `tests/fixtures/players`. Для проверки текущей сети и плееров на VM используется `python scripts/check-live-players.py --report /private/path/report.json --catalog`. Проверка получает свежие ссылки, читает HLS и ограниченный образец медиаданных; полный файл и Google Drive не затрагиваются. Новые публичные примеры передаются через `--sample 'Player=https://...'`. Отчёт отличает успешную отдачу медиа от ошибки и не превращает пропущенную проверку в успех.

Поддерживаются прямые HTTPS MP4, HLS VOD с TS/fMP4, диапазонами байтов и отдельной аудиодорожкой. Обычный AES-128 HLS с публичным ключом поддерживается; DRM, SAMPLE-AES, сессионные лицензии, платный доступ и закрытые аккаунты не обрабатываются. HLS сначала полностью локализуется на сервере; ffmpeg читает только локальные файлы и не получает сетевые URL.

Сайт может менять разметку, выдавать CAPTCHA, убирать видео, ограничивать регион или показывать плеер только после динамического запроса. Поэтому ссылка на YummyAnime/AnimeGo/Jut.su/AnimeVost/AniLibria не гарантирует извлечение. Если опубликованный список серий или поток отсутствует в доступном HTML, используй отдельные публичные ссылки серий/поддерживаемого плеера либо прямой MP4/HLS. Номера эпизодов не придумываются по заявленному количеству. Автоматический обход браузерных проверок не установлен. Исходный код устроен так, чтобы добавлять адаптеры конкретной разметки без смены хранилища и интерфейса.

## Шифрование и папки

- AES-256-GCM; PBKDF2-SHA256, 310 000 итераций; случайные salt и IV. Блок — 4 МиБ. ID файла и номер блока входят в authenticated additional data.
- Каталог содержит названия и сведения о коллекциях внутри шифрования. Дерево Drive: раздел («Аниме», «Манга», «Ранобэ», «Книги», «Музыка») → отдельная папка тайтла `collection-UUID` → при наличии сезон/том `part-UUID` → отдельный файл `asset-UUID` → `part-NNNNNN.enc`. Личные видео и изображения имеют дополнительные разделы «Видео»/«Фото». Названия тайтлов и сезонов/томов показаны на сайте после расшифровки, а в Drive для них используются непрозрачные ID. Серверный импорт также сохраняет `manifest.enc.json`.
- Локальные файлы шифрует браузер до отправки; серверный импорт шифрует VM до отправки в Drive. Фраза не отправляется серверу; производный ключ хранится в памяти браузера и в зашифрованной записи активного задания на своём сервере. Токены/ключи не публикуются в репозитории и не сохраняются в localStorage.
- Service Worker расшифровывает блоки для просмотра в памяти и поддерживает HTTP Range/перемотку. CacheStorage содержит только зашифрованные блоки, до 160 блоков. Сеансы разделены по вкладкам.
- При просмотре видео трафик Drive → устройство необходим. Рекомендуемый формат — MP4 H.264/AAC. Остальные кодеки зависят от браузера. Резервный режим скачивает файл целиком и требует соответствующего объёма RAM.
- Изображения, TXT, PDF, EPUB и CBZ/ZIP открываются в приложении. Книги и архивы скачиваются целиком. JSZip/EPUB.js загружаются с закреплённых версий CDN.

## Разработка и проверки

Node.js 22.12+, Python 3.10+, ffmpeg/ffprobe и Chromium:

```sh
cd media-vault
npm ci
python -m pip install -r server/requirements-service.txt httpx==0.28.1
npm run dev
```

Проверки перед публикацией:

```sh
npm test
npm run test:server
npm run test:notebook
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
CHROMIUM_PATH=/usr/bin/chromium MEDIA_VAULT_SKIP_BUILD=1 npm run test:browser
```

Тесты используют настоящие AES-GCM/Web Crypto, ffmpeg, TS/fMP4-видео и подменённые HTTP/Google Drive. Проверяются совместимость Python ↔ браузер, диапазоны, шифрование, раскладка папок, восстановление, отсутствие видеозапросов из формы импорта, читатель без записи и размеры экрана 320/390/768/1280. Они не заменяют вход в реальный Google и проверку на физическом Android/iPhone. Отдельная проверка криптографии — `selftest.html`.

Старый Colab-блокнот оставлен для совместимости с прежними заданиями и не используется интерфейсом. После изменения его общих `server/*.py` или зависимостей выполни `python scripts/build-notebook.py`: блокнот содержит контрольные суммы источников, проверяемые до авторизации, и публикуется без результатов выполнения.

## Совместимость видеокодеков

Импорт использует remux (`ffmpeg -c copy`): исходный кодек не меняется. Для максимальной совместимости нужны MP4, H.264 и AAC. Плеер различает ошибки Drive/Service Worker/Range и неподдерживаемые кодеки. Резервный режим загружает файл целиком и требует памяти устройства.

## Единая версия, страницы тайтлов и оформление

Основной репозиторий — **Onikri/MediaVault**, основной адрес — https://onikri.github.io/MediaVault/. Динамический поиск, HTML-парсеры, выбор озвучки/серий и протокол автоматического Oracle-импорта перенесены из `hots_tank.github.io/media-vault`. Существующий Oracle-сервер, OAuth-клиент, callback, каталог Drive и ключи библиотеки не заменяются. Оба адреса используют origin `https://onikri.github.io`, поэтому разрешённый origin Google и сервера прежний. Новую библиотеку для перехода создавать не нужно.

Каждый тайтл имеет страницу с фоном, обложкой, эпизодами, русским описанием, характеристиками, персонажами, связанными сезонами/мангой/ранобэ и личной оценкой. Видео открывается в этой странице. Отдельный полноэкранный режим включается пользователем. Представления библиотеки: плитки, маленькие плитки, список и таблица; фильтры по жанру, году и озвучке доступны и на телефоне.

Русское описание и персонажи берутся из публичного бесплатного каталога Шикимори. Английский синопсис не подставляется вместо русского. При недоступности источника приложение показывает сохранённую копию либо честное сообщение и возможность повторить запрос. Обзоры и обсуждения открываются по ссылке источника; собственная система комментариев пока не создаётся.

Снимок метаданных и личные оценки хранятся **внутри зашифрованного каталога Drive**. Обложки, фоны, кадры и портреты сохраняются как отдельные AES-GCM файлы с непрозрачными именами внутри папки тайтла. Расшифрованные Blob URL живут только в памяти открытой библиотеки и отзываются при выходе. После сохранения страница не обращается к исходному сайту за кешированными данными и изображениями. Если сайт запретил чтение изображения через CORS, оно не подменяется чужим; доступна повторная загрузка. Для новых импортированных тайтлов с известным MAL/Shikimori ID обогащение запускается последовательно при открытой библиотеке владельца с правом записи. После обычного входа только с правом чтения сохранение оформления один раз запросит доступ к записи Drive. Сами видеобайлы импортирует Oracle, через устройство они не проходят.

Запись снимка обновляет каталог перед сохранением и использует `If-Match`, когда Drive возвращает ETag; конфликт 412 перечитывает каталог. Обычная запись оформления при активном серверном импорте откладывается. Пароль Google и секретная фраза на сервер не отправляются; для задания импорта владелец передаёт только производный ключ открытой библиотеки своему серверу.

## Плеер и Anime4K

Геометрия видео одинакова при паузе и воспроизведении. Панорама и описание плавно меняют прозрачность, без перемещения нижнего края. Параллакс отключается при `prefers-reduced-motion`. Компактные настройки открываются возле кнопки на десктопе, на телефоне — небольшой панелью снизу; разделы: «Просмотр», «Изображение», «Субтитры», «Действия». Поддерживаются клавиатура, управление фокусом и закрытие Escape.

**Anime4K ×2** — настоящий WebGL-порт алгоритмов Anime4K 4.0.1 из `anime4k.js` 1.1.3 (MIT), загружаемый отдельным локальным JS-чанком при включении. Каждый уже декодированный кадр обрабатывается на устройстве; видеокадры никуда не отправляются. Экономный и сбалансированный профили используют небольшой CNN-профиль, режим качества — средний. Размер входа ограничивается по выбранному профилю и типу устройства; на телефоне экономный режим ограничен 640 px по ширине. Выход ×2 относится к рабочему размеру обработки, а не обещанию физического 4K для любого исходника. Нужны WebGL и расширения float textures. При потере GPU-контекста, ошибке или чрезмерно медленной обработке включается исходное видео. Работа на любом телефоне и гарантированная частота кадров не обещаются: физический GPU устройства определяет скорость. В PiP выводится нативное видео.

FSRCNN ×2 через ONNX/WebGPU сохранена как отдельный вариант. SRT/VTT, скорость, озвучки, разметка и пропуск опенинга, сохранение позиции, скриншот, клип до 30 секунд, PiP и горячие клавиши сохранены. Доступность озвучки и качества зависит от реально сохранённых вариантов; плеер не придумывает отсутствующие дорожки.

## Проверка объединения

`npm test`, `npm run test:server`, `npm run test:notebook`, `npm run build`, `npm run test:ui`, `npm run test:browser`.

Браузерные тесты используют поддельных Google/Drive-провайдеров и настоящие AES-GCM, Service Worker, H.264 MP4 и WebGL-шейдеры. Проверяются импорт без видеотрафика устройства, повторное открытие страницы из Drive без внешних запросов, русские персонажи, оценки, варианты библиотеки, неизменный размер видео при паузе и разрешения зрителя. Реальные Google OAuth/ACL и физические Android/iOS требуют проверки в аккаунте владельца.


### Полноэкранная атмосфера страницы

Фон страницы — медленное слайд-шоу оригинальных кадров Шикимори и доступного панорамного изображения AniList, сопоставленного строго по MAL ID. Используется максимальный размер, опубликованный источником, без объявления маленькой картинки настоящим 4K. Крупные файлы перед сохранением ограничиваются 2560 px и высококачественной WebP-копией. Смена кадра раз в 10 секунд с растворением 1.8 секунды, кнопками остановки и ручного перехода; reduced motion выключает автоматическую смену и параллакс. Палитра извлекается локально из уже полученных изображений. Акцент осветляется до контраста не меньше 5:1 к тёмной поверхности; текст находится на тёмных панелях. На телефоне отключены тяжёлые размытия фона.

Связи Шикимори дополняются бесплатными Wikidata только через подтверждённую ссылку Wikipedia и явные связи «первоисточник / произведение по мотивам». Таким образом могут появляться книги, фильмы и игры. Названия по похожему написанию не считаются доказательством связи. Для игр открывается страница с данными и ссылка на официальный источник; игровой файл не импортируется аниме-парсером. Данные связей и источники сохраняются вместе с профилем тайтла.

## Запоминание устройства и биометрия

В окне cookies можно выбрать «Только необходимые» или «Принять и запомнить». Рекламных cookies и аналитики нет. Cookie хранит только этот выбор. Запоминание входа добровольное; его также можно включить и отключить в профиле. После первого входа и открытия библиотеки последующие открытия на этом устройстве восстанавливают аккаунт и библиотеку автоматически.

Долговременный Google refresh token хранится зашифрованным на своём Oracle. Браузер сохраняет в IndexedDB неизвлекаемый ECDSA-ключ устройства и подписывает одноразовые запросы восстановления; короткий Google access token остаётся в памяти. Регистрация устройства действует до 90 дней, но Google может отозвать разрешение раньше. В режиме Testing у Google OAuth фоновое разрешение может потребовать повторного согласия через 7 дней — cookie не отменяет это правило Google. Зритель разрешает только чтение Drive; импорт и изменения библиотеки всё так же доступны только проверенному владельцу.

Для быстрого открытия на личном устройстве производный ключ библиотеки заворачивается локальным неизвлекаемым AES-GCM ключом. **Секретная фраза нигде не сохраняется.** На общем устройстве эту возможность включать не следует. «Выйти» удаляет текущую регистрацию входа и ключ быстрого открытия; «Забыть устройство» очищает локальное защищённое хранилище. Фоновое разрешение Oracle на импорт при выходе с телефона сохраняется.

Дополнительная защита библиотеки — WebAuthn с обязательной проверкой пользователя и PRF. Браузер предлагает отпечаток, лицо или защищённый PIN. Ключ расшифровывается результатом PRF, а не просто после декоративного биометрического окна. Если PRF недоступен, приложение сообщает об этом; секретная фраза продолжает работать. Нативный способ проверки определяет Android/браузер.

## Скорость, очередь и заполнение библиотеки

Импортер скачивает до четырёх HLS-сегментов параллельно, собирает MP4 через `ffmpeg -c copy` без перекодирования видео и отправляет два независимых зашифрованных блока Drive одновременно. Размер блока и AES-GCM/AAD совместимы с прежней библиотекой. Drive IDs выделяются пачками по 128, каждый поток использует собственный HTTP-клиент. Сетевые операции Drive имеют таймаут 30 секунд; HTML-проверки источников имеют общий предел времени. Показаны скорость записи, время AES-GCM и позиция в очереди. Задания чередуются после каждой серии, чтобы сезон на десятки файлов не блокировал отдельную серию другого задания.

Шикимори подключён через актуальный `shikimori.io`, включая роли, описания персонажей, кадры и связи. Неполное оформление помечается для повторной синхронизации. Публичный прокси изображений принимает только известные домены обложек/кадров, ограничивает размер и тип, кеширует ответ; видеотрафик через него не идёт.

Новые серии получают собственный JPEG-кадр из видео, до 1280 px по ширине. Для существующих файлов «Синхронизировать оформление» добавляет фоновое задание: ffmpeg читает нужные диапазоны через локальный расшифровывающий поток Oracle, без полной загрузки файла в браузер. Превью, фоны и русские сведения сохраняются зашифрованными в Drive. Отдельная обложка не используется как фон; кадры из собственной серии помогают оформить страницу и при недоступности внешней галереи.

Добавлены HTML-адаптеры AnimeJoy и SovetRomantica; поиск озвучек больше не ограничен двумя сайтами. AniLiberty читает опубликованную JSON-гидратацию HTML, если она есть. API видеосайтов, DRM, платный доступ и проверки Cloudflare не обходятся. Доступность конкретного сайта/IP отражается в результатах, пустой HTML не считается найденным сезоном.

## Android, планшеты и GPU

В настройках изображения появился профиль «Телефон / Android», «Планшет», «Компьютер» и автоматический выбор. Лёгкий мобильный режим выполняет кубическую интерполяцию с ограниченным усилением деталей в WebGL прямо из видеотекстуры: нейросеть на CPU не запускается. На компьютере автоматический режим использует Anime4K; FSRCNN/WebGPU доступна отдельно. После ошибки или потери контекста можно повторить запуск на новом canvas. Показаны обработчик, размер кадра, скорость и, если браузер разрешил, имя рендерера; программный рендерер отмечается явно. Сайт не может включить аппаратное ускорение вместо пользователя, если оно запрещено браузером или драйвером.

гарантией доступности каждого сайта или наличия всех переводов мира.
