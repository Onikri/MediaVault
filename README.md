# MediaVault

Мобильная медиатека на React/Vite: манга, видео, книги, музыка и изображения в собственном Google Drive. Новый интерфейс использует Radix UI, Motion и Lucide. В библиотеке показываются реальные файлы из расшифрованного каталога.

**Сайт:** https://onikri.github.io/MediaVault/

**Серверный импорт:** [Открыть бесплатный Colab-блокнот](https://colab.research.google.com/github/Onikri/MediaVault/blob/main/notebooks/MediaVault_Server_Import.ipynb)

## Первый запуск

1. Открой **Профиль → Войти через Google** и разреши чтение файлов Drive в окне Google. Отдельная кнопка подключения и ввод ID не требуются: приложение само ищет библиотеку после входа. Владелец — аккаунт `roma.shevchenko2020@gmail.com`. В коде хранится SHA-256 адреса для определения администратора. Папка другого аккаунта не используется: `storageFolderId` пустой, новая библиотека создаётся в Drive вошедшего владельца.
2. Если библиотека найдена, введи только её секретную фразу. Если библиотек пока нет, придумай и повтори фразу длиной от 12 символов → **Создать мою библиотеку**. Папка, зашифрованный каталог и ID создаются автоматически. Фразу нужно придумать самому: это не пароль Google, получить её в Google Cloud нельзя. Сохрани её, восстановления нет.
3. В **Библиотеке** можно добавлять локальные файлы или папку целиком. Формат определяется автоматически. Разделы «Аниме», «Манга», «Ранобэ», «Книги», «Музыка» отделены друг от друга. Укажи название тайтла/альбома и при необходимости сезон/том. При выборе папки дерево вроде `Ранобэ/Название/Том 1/...` разбирается автоматически. EPUB/PDF сам по себе не отличает ранобэ от обычной книги — раздел можно выбрать вручную.
4. Если найдено несколько библиотек, выбери нужную из списка. Проверка Drive не создаёт файлов; при ошибке доступа новая пустая библиотека не предлагается. Перед созданием приложение повторно проверяет наличие каталога, чтобы избежать случайных дубликатов. Для редкого ручного открытия достаточно вставить полную ссылку в «У меня есть ссылка на другую библиотеку».

Кнопка **Пригласить** выдаёт другу право чтения папки в Drive. Передай ссылку и секретную фразу отдельно. Для зрителя приложение запрашивает только чтение Drive.

Вход сразу запрашивает чтение Drive. При создании или первом изменении библиотеки Google может дополнительно попросить разрешить запись; это происходит из соответствующего действия автоматически. Зрителям доступ на запись не запрашивается.

Публичный Google OAuth Web Client ID уже указан в `config.js`. Пароль Google, Client Secret, ключи сервисного аккаунта и токены приложению не нужны. Если Google отклоняет вход, в проекте OAuth должны быть включены Drive API, origin `https://onikri.github.io` и тестовые пользователи, включая владельца. Для локального запуска origin — `http://localhost:8080`. В origin нельзя добавлять путь проекта.

## Разделы и тайтлы

Одна библиотека — общий корень хранилища и одна секретная фраза. Это не общая папка со всеми сериями вперемешку. В режиме «Тайтлы» каждый тайтл показан отдельной карточкой; внутри находятся сезоны, тома и файлы. В режиме «Файлы» доступен общий список. Поиск работает по названию тайтла и файла.

```text
MediaVault
├── Аниме → Наруто → Сезон 1 / Сезон 2 → серии
├── Манга → Наруто → Том 1 / Том 2 → главы
├── Ранобэ → Название → тома
├── Книги → Название книги → файлы
└── Музыка → Альбом → треки
```

Одноимённые аниме, манга и ранобэ имеют разные папки. Сезоны одного аниме используют общую папку тайтла. Старые каталоги и ссылки на зашифрованные блоки читаются без перемещения или повторного шифрования существующих файлов; новые загрузки используют расширенную структуру `storage.version = 2`.

## Загрузка аниме на сервере Google

Схема: **публичный источник → Google Colab → зашифрованный Google Drive**.

Видео при импорте не проходит через устройство, GitHub Pages или Cloudflare Worker. Google Drive API сам не скачивает произвольные URL и не собирает HLS, поэтому эти операции выполняет бесплатная сессия Colab на сервере Google. Cloudflare-аккаунт, платный хостинг, GPU и банковская карта не требуются.

1. Открой библиотеку владельца → **Импорт**. Вставь ссылку на сезон/серию/плеер, либо список ссылок серий по одной на строку.
2. Укажи название аниме, номер сезона, серии (`all`, `1-12`, `1,3,5-8`) и качество. Название не должно включать номер сезона: повторные сезоны сохраняются внутри того же тайтла.
3. Нажми **Подготовить серверный импорт → Скопировать задание → Открыть Google Colab**.
4. В Colab выбери **Среда выполнения → Выполнить всё**. Вставь задание в поле запроса. Кнопка сайта копирует JSON одной строкой; в нём только ссылки, ID каталога и параметры.
5. Авторизуй аккаунт владельца стандартным способом Google и введи секретную фразу в скрытое поле `getpass`. Не вставляй её в код, JSON или сообщения.
6. Дождись завершения и нажми **Обновить библиотеку** на сайте.

Импорт обрабатывает одну серию за раз: разбирает публичный HTML/плеер, получает MP4/HLS, скачивает сегменты на Colab, собирает MP4 с ffmpeg, проверяет видео через ffprobe, шифрует и загружает в Drive. Временные файлы удаляются после серии. Google credentials используются только адаптером Drive; cookies и заголовки авторизации Google не отправляются источникам.

После каждой серии записывается каталог и зашифрованный манифест восстановления. При повторном задании завершённые серии пропускаются. Если запись каталога прервалась после загрузки зашифрованного видео, манифест позволяет вернуть его в каталог. Незавершённая серия скачивается заново.

Бесплатные сессии Colab имеют переменные ограничения длительности, диска и доступности. Фоновой работы 24/7 нет; платные ресурсы автоматически не включаются. Должно хватать свободного места в Drive. Пока Colab записывает каталог, не загружай и не изменяй библиотеку параллельно: Drive v3 не обещает атомарную запись каталога, хотя реализованы перечитывание, слияние и проверка результата.

## Парсер без API аниме-сайтов

Собственный `server/source_parser.py` извлекает ссылки и опубликованные эпизоды из HTML, `iframe`, атрибутов плееров и текстовой конфигурации. Для получения потоков из публичных плееров используются открытые наработки [anime-dl-core 0.5.1](https://github.com/ialakey/anime-dl-core), MIT: **Kodik, Aniboom, Sibnet и Animedia**. Это не поиск через API этих сайтов; ключ разработчика не требуется. API-адаптеры AniLibria, CVH и Alloha намеренно не зарегистрированы. REST/GraphQL-адреса блокируются клиентом источников.

Поддерживаются прямые HTTPS MP4, HLS VOD с TS/fMP4, диапазонами байтов и отдельной аудиодорожкой. Обычный AES-128 HLS с публичным ключом поддерживается; DRM, SAMPLE-AES, сессионные лицензии, платный доступ и закрытые аккаунты не обрабатываются. HLS сначала полностью локализуется в Colab; ffmpeg читает только локальные файлы и не получает сетевые URL.

Сайт может менять разметку, выдавать CAPTCHA, убирать видео, ограничивать регион или показывать плеер только после динамического запроса. Поэтому ссылка на YummyAnime/AnimeGo/Jut.su/AnimeVost/AniLibria не гарантирует извлечение. Если опубликованный список серий или поток отсутствует в доступном HTML, используй отдельные публичные ссылки серий/поддерживаемого плеера либо прямой MP4/HLS. Номера эпизодов не придумываются по заявленному количеству. Автоматический обход браузерных проверок не установлен. Исходный код устроен так, чтобы добавлять адаптеры конкретной разметки без смены хранилища и интерфейса.

## Шифрование и папки

- AES-256-GCM; PBKDF2-SHA256, 310 000 итераций; случайные salt и IV. Блок — 4 МиБ. ID файла и номер блока входят в authenticated additional data.
- Каталог содержит названия и сведения о коллекциях внутри шифрования. Дерево Drive: раздел («Аниме», «Манга», «Ранобэ», «Книги», «Музыка») → отдельная папка тайтла `collection-UUID` → при наличии сезон/том `part-UUID` → отдельный файл `asset-UUID` → `part-NNNNNN.enc`. Личные видео и изображения имеют дополнительные разделы «Видео»/«Фото». Названия тайтлов и сезонов/томов показаны на сайте после расшифровки, а в Drive для них используются непрозрачные ID. Серверный импорт также сохраняет `manifest.enc.json`.
- Локальные файлы шифрует браузер до отправки; серверный импорт шифрует Colab до отправки в Drive. Ключ и фраза не сохраняются в репозитории, задании или localStorage. Авторизацией Colab управляет Google; по окончании отключись и удали среду выполнения.
- Service Worker расшифровывает блоки для просмотра в памяти и поддерживает HTTP Range/перемотку. CacheStorage содержит только зашифрованные блоки, до 160 блоков. Сеансы разделены по вкладкам.
- При просмотре видео трафик Drive → устройство необходим. Рекомендуемый формат — MP4 H.264/AAC. Остальные кодеки зависят от браузера. Резервный режим скачивает файл целиком и требует соответствующего объёма RAM.
- Изображения, TXT, PDF, EPUB и CBZ/ZIP открываются в приложении. Книги и архивы скачиваются целиком. JSZip/EPUB.js загружаются с закреплённых версий CDN.

## Продвинутый видеоплеер

Плеер открывается из видеокарточки и использует тот же зашифрованный поток Service Worker. Доступны:

- **Сезоны и серии.** Переключение внутри тайтла; серия определяется из поля episode или имени вроде S01E02.mp4, 02.mp4, серия 12.mp4. Если номер неизвестен, файл остаётся отдельным эпизодом.
- **Озвучки.** Файлы одного сезона с одинаковым номером серии объединяются как версии; подписи берутся из необязательных полей voice, dub, dubbing, translation, audioLabel или квадратных скобок имени. Для нескольких аудиодорожек в одном видео выбор отображается **только если** браузер предоставляет HTMLMediaElement.audioTracks. Для гарантированного выбора между несколькими озвучками лучше импортировать отдельный видеофайл каждой версии с одинаковым episode.
- **Субтитры.** Выбор доступных браузеру текстовых дорожек и локальная загрузка .srt/.vtt до 5 МБ. Локальные субтитры преобразуются в WebVTT **в памяти** и не отправляются в Drive. Встроенные в MKV/MP4 субтитры могут быть недоступны в браузере — при необходимости экспортируй их в VTT/SRT.
- **Пропуск опенинга.** Если у элемента каталога есть opening: {start, end} (секунды), кнопка появляется в этом интервале. Любой зритель может открыть настройки, поставить видео на начало/конец опенинга и нажать **Начало** и **Конец**; разметка хранится локально для данного файла. Автоматический пропуск включается отдельно. Таймкоды не угадываются.
- **Управление.** Перемотка, пауза, громкость, скорость 0.5–2×, полноэкранный режим, PiP (при поддержке), автоматический переход к следующей серии, сохранение позиции просмотра в localStorage устройства. Горячие клавиши: пробел/K — пауза, J/← и L/→ — ±10 секунд, F — полный экран, M — без звука. Настройки сохраняются локально.
- **Нейросетевой апскейлинг (FSRCNN ×2).** Плеер загружает проверенные предобученные веса **FSRCNN** (ONNX, Apache-2.0) и выполняет реальные свёрточные вычисления через **ONNX Runtime Web на WebGPU**. Кадр преобразуется в яркостный канал Y, нейросеть восстанавливает его с увеличением ×2, затем он объединяется с цветом исходного кадра. Режимы: экономный (320px), баланс (480px), качество (640px), с автоматическим ограничением слишком медленного инференса. Это не WebGL-фильтр. Первое включение требует загрузки ONNX Runtime Web (~27 МБ WebGPU/WASM-движка) и 35-КБ весов по публичным HTTPS-адресам; видеокадры остаются в браузере. Нужен WebGPU и достаточно быстрый GPU. На неподдерживаемых или слабых устройствах плеер показывает исходное видео. PiP выводит нативное видео, без обработки.

Для импорта нескольких озвучек и внешних субтитров на сервер требуется отдельно добавить их получение и сохранение в каталог. Текущий Colab-импорт, как и прежде, сохраняет только извлечённый/собранный видеофайл, а не все отдельные дорожки источника. Плеер не добавляет DRM-декодирование или неподдерживаемые браузером кодеки. Эффект нейросети зависит от качества исходника и быстродействия устройства; 30/60 FPS не гарантируются.


### Если видео не воспроизводится

- Сайт GitHub Pages публикуется **только из main**. Новые компоненты открытого PR не появляются на опубликованном сайте, пока PR не слит.
- Нажми **Профиль → Обновить доступ к файлам**, затем **Обновить библиотеку** и открой серию ещё раз. Service Worker работает только после получения сеанса расшифровки. Если поток не работает, воспользуйся кнопкой **Загрузить файл целиком (резервный режим)**; большие видео при этом требуют много памяти.
- Если резервная загрузка воспроизводится, а поток — нет, вероятна проблема Service Worker / Google Drive / HTTP Range. Если **оба режима** не воспроизводятся, особенно для импортированных аниме, проверь кодеки.
- Импорт сейчас применяет remux с ffmpeg -c copy. Он меняет контейнер, но **не преобразует** HEVC/H.265, AV1, Dolby AC-3 и другие кодеки, которые браузер может не поддерживать. Чтобы получить максимально совместимый MP4, перекодируй исходный файл и загрузи его снова:

```sh
ffmpeg -i "source.mkv" -map 0:v:0 -map 0:a:0? \
  -c:v libx264 -pix_fmt yuv420p -crf 21 -preset medium \
  -c:a aac -b:a 192k -movflags +faststart "browser-ready.mp4"
```

- В новом плеере при ошибке запуска выполняется локальная проверка ответа потока и кодеков в заголовке MP4. Диагностика не отправляет видео на сторонний сервер и не раскрывает ключ шифрования.


### Сенсорное управление плеером

Жесты доступны на сенсорных устройствах поверх изображения, вне кнопок и панелей:

- короткий тап — Play/Pause;
- горизонтальный свайп — предпросмотр позиции на таймлайне; переход применяется при отпускании;
- вертикальный свайп слева — яркость изображения внутри плеера (не системная яркость);
- вертикальный свайп справа — громкость;
- из центральной трети вверх — раскрыть существующую ленту эпизодов на весь плеер;
- из центральной трети вниз — открыть настройки и действия.

Начальное направление фиксируется после 12 px движения. Отменённый жест не применяет перемотку. На десктопе мышь управляет обычными кнопками и таймлайном. Кнопка рядом с числом эпизодов раскрывает ту же ленту без жеста.

В настройках доступны ссылка на эпизод с текущей позицией, PNG-кадр и запись клипа до 30 секунд. Клип записывает воспроизводимый исходный поток без микрофона; запись останавливается кнопкой или в конце видео. При закрытии плеера незавершённая запись отменяется. Кадр учитывает активный AI-canvas. Наличие вариантов качества зависит от файлов в каталоге; плеер не создаёт новые разрешения транскодированием. Мини-окно использует браузерный PiP. Доступность PiP, записи и управления программной громкостью зависит от браузера; на физических телефонах требуется отдельная проверка.
